# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

本章では、必須8カラムを持つ単一店舗のCSVを対象に、入力検査、日次集計、バッチ連携を組み立てる。使用するのはPython標準ライブラリだけである。

ここで算出する人件費は「実労働分数×時給」の基本部分であり、給与確定額ではない。深夜割増、時間外割増、休日割増などは、時刻明細や勤務制度を参照する別工程で計算する。必要情報がないものをゼロとして処理しないことが、運用の出発点となる。

## 7.1 入力契約を先に固定する

CSVはUTF-8とし、先頭の文字マークがあるファイルも読めるようにする。日付は `YYYY-MM-DD`、分数は0以上の整数、金額は桁区切りのない数値とする。識別子は文字列として読み、先頭のゼロを維持する。

`shift_id` はファイル内で一意、`staff_id` は従業員の照合キーとする。氏名の一致だけで別行をまとめない。`daily_sales_target` は同じ日の全行で一致させ、日次集計では一度だけ使用する。

以下は、ヘッダーの重複、列数の不一致、欠損、重複識別子、数値形式を検査する読込部分である。

```python
import csv
import re
from datetime import date
from decimal import Decimal

FIELDS = (
    "shift_id", "work_date", "staff_id", "staff_name",
    "work_minutes", "break_minutes",
    "hourly_wage", "daily_sales_target",
)

def minute_value(text):
    if not re.fuテキスト処理系atch(r"[0-9]+", text):
        raise ValueError("分数は0以上の整数")
    return int(text)

def money_value(text):
    if not re.fuテキスト処理系atch(r"[0-9]+(?:\.[0-9]+)?", text):
        raise ValueError("金額形式が不正")
    value = Decimal(text)
    if not value.is_finite():
        raise ValueError("有限の金額が必要")
    return value

def read_shifts(path):
    result = []
    seen = set()
    with open(path, encoding="utf-8-sig", newline="") as f:
        reader = csv.DictReader(f)
        names = reader.fieldnames or []
        if len(names) != len(set(names)):
            raise ValueError("ヘッダーが重複")
        if set(names) != set(FIELDS):
            raise ValueError("ヘッダーが仕様と不一致")

        for line, row in enumerate(reader, start=2):
            try:
                if None in row or any(
                    value is None for value in row.values()
                ):
                    raise ValueError("列数が不一致")
                row = {
                    key: value.strip()
                    for key, value in row.items()
                }
                if any(not row[key] for key in FIELDS):
                    raise ValueError("必須値が空欄")
                key = row["shift_id"]
                if key in seen:
                    raise ValueError("シフト識別子が重複")

                day = row["work_date"]
                if not re.fuテキスト処理系atch(r"\d{4}-\d{2}-\d{2}", day):
                    raise ValueError("日付形式が不正")
                date.fromisoformat(day)

                for key in ("work_minutes", "break_minutes"):
                    row[key] = minute_value(row[key])
                for key in ("hourly_wage", "daily_sales_target"):
                    row[key] = money_value(row[key])
                if row["hourly_wage"] <= 0:
                    raise ValueError("時給は正数が必要")

                seen.add(row["shift_id"])
                result.append(row)
            except ValueError as exc:
                raise ValueError(
                    f"CSV行{line}: {exc}"
                ) from exc
    if not result:
        raise ValueError("勤務データが空")
    return result
```

最初の異常で停止する設計は、誤った行を除いて残りだけ集計する事故を防ぐ。大量修正が必要な現場では全件の異常を収集してもよいが、異常が残るファイルを正式結果へ昇格させない点は維持する。

## 7.2 日次集計と停止理由を分ける

休憩は従業員と日付で合算し、人件費は日付で集計する。このコードは、各行の労働と休憩が重複していないこと、`work_date` が休憩検査に使う労働日を表すことを前提とする。分割勤務や日またぎ勤務では、先に明細との整合を確認する。

人件費率の上限は例として30％とする。比較には丸め前の金額を使い、表示の丸めで合否が変わらないようにする。

```python
from collections import defaultdict
from decimal import ROUND_HALF_UP

def required_break(minutes):
    if minutes > 480:
        return 60
    if minutes > 360:
        return 45
    return 0

def inspect(rows, limit=Decimal("0.30")):
    people = defaultdict(lambda: [0, 0])
    costs = defaultdict(lambda: Decimal("0"))
    targets = defaultdict(set)

    for row in rows:
        day = row["work_date"]
        person = (day, row["staff_id"])
        people[person][0] += row["work_minutes"]
        people[person][1] += row["break_minutes"]
        costs[day] += (
            Decimal(row["work_minutes"])
            * row["hourly_wage"] / Decimal("60")
        )
        targets[day].add(row["daily_sales_target"])

    issues = []
    for (day, staff), (work, rest) in sorted(people.items()):
        shortage = max(0, required_break(work) - rest)
        if shortage:
            issues.append({
                "kind": "break_shortage",
                "work_date": day,
                "staff_id": staff,
                "minutes": shortage,
            })

    daily = []
    for day in sorted(costs):
        values = targets[day]
        if len(values) != 1:
            issues.append({
                "kind": "sales_conflict",
                "work_date": day,
            })
            continue

        target = next(iter(values))
        cost = costs[day]
        if target == 0:
            issues.append({
                "kind": "sales_zero",
                "work_date": day,
            })
            ratio = None
        else:
            ratio = cost / target
            if cost > target * limit:
                issues.append({
                    "kind": "cost_over",
                    "work_date": day,
                })

        daily.append({
            "work_date": day,
            "base_cost_yen": str(cost.quantize(
                Decimal("1"), rounding=ROUND_HALF_UP
            )),
            "sales_target": str(target),
            "base_cost_ratio": (
                None if ratio is None else str(ratio)
            ),
        })
    return {"daily": daily, "issues": issues}
```

売上目標ゼロは、ゼロ除算を避けるだけで終わらせない。休業日の研修など、売上を伴わない勤務である可能性もあるため、比率を未算定として理由を確認する。目標が混在する日は、都合のよい値を採用せず停止対象とする。

また、この集計は勤務行のある日だけを扱う。営業予定日なのに勤務データがないケースは、営業日一覧との照合で検出する必要がある。入力検査に通ることと、入力がそろっていることは別の確認事項である。

## 7.3 ファイルを安全に受け渡す

バッチでは、処理途中のファイルを次工程が読まない仕組みが必要になる。出力先と同じディレクトリに一時ファイルを書き、書込完了後に置き換える。

```python
import json
import os
import tempfile
from pathlib import Path

def write_report(path, report):
    path = Path(path)
    temp = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w",
            encoding="utf-8",
            dir=path.parent,
            prefix=".report-",
            suffix=".tmp",
            delete=False,
        ) as f:
            temp = Path(f.name)
            json.dump(
                report, f, ensure_ascii=False, indent=2
            )
            f.write("\n")
            f.flush()
            os.fsync(f.fileno())
        os.replace(temp, path)
    finally:
        if temp is not None and temp.exists():
            temp.unlink()
```

この方法は、読者が書込途中のJSONを開くことを防ぐための基本策である。複数処理の同時実行防止や、異なる保存先での動作保証まで担うものではない。実行ごとに固有の出力先を使い、スケジューラー側でも同じ対象の重複起動を抑止する。

日次の実行順序は次のように固定する。

1. 入力側が一時名でCSVを書き、完了後に正式名へ変更する。
2. 検査側がその入力を実行専用の保管先へ確保する。
3. 構造検査、業務検査、明細照合を順に実行する。
4. 結果、入力の指紋、設定、実行日時を保存する。
5. 合格と承認を確認した実行だけを後続処理へ渡す。

終了コードは、正常を0、構造不正を2、業務上の停止を3、入出力障害などを4と決めておく。コード0でも割増未計算なら給与連携は許可しない。工程ごとの完了状態を別項目で保持する。

同じ入力を再実行しても、給与取込が二重にならないよう、後続側で取込済みの実行識別子を記録する。修正版は旧版を黙って上書きせず、置換対象と差額が追える形で渡す。

## 7.4 月次締めに応用する

月次では、日次結果の金額を足すだけでは不十分である。週をまたぐ時間外判定や、月末をまたぐ勤務があるため、必要な前後期間の明細も参照する。日次の表示丸めを積み上げず、定めた精度の元データから締め処理を行う。

入力の指紋には `hashlib` を使える。対象は、検査で実際に読んだ固定済みファイルとする。

```python
import hashlib

def file_digest(path):
    digest = hashlib.sha256()
    with open(path, "rb") as f:
        for block in iter(lambda: f.read(1024 * 1024), b""):
            digest.update(block)
    return digest.hexdigest()
```

実行台帳には、実行識別子、対象期間、入力の指紋、処理版、設定版、入力件数、実労働合計、結果保存先、承認者を残す。指紋は内容の一致確認に役立つが、それだけで承認や改変防止を保証するわけではない。保管先の権限と履歴管理も必要になる。

締め後の訂正は、訂正対象の実行を明示して再計算する。修正前後で件数、分数、基本部分、割増部分、支給額を比較し、差が出た理由を記録する。対象外の従業員まで変動していれば、設定変更や結合条件の誤りを疑う。

## 7.5 実務監査チェックリスト

日次確認では、計算結果の正しさと勤務計画の実行可能性を合わせて見る。

- [ ] 必須8カラムがそろい、識別子の重複と欠損がない。
- [ ] 実労働時間から休憩を二重に控除していない。
- [ ] 分割勤務の合算と休憩の重複確認が済んでいる。
- [ ] 予定休憩を取得実績として流用していない。
- [ ] 休憩中の交代要員と最低配置人数を確保できる。
- [ ] 同日の売上目標が一致し、重複合計していない。
- [ ] 売上ゼロと勤務データ欠落を区別している。
- [ ] 人件費の対象範囲と未計算項目を表示している。

月次確認では、期間の完全性と支給への接続を確認する。

- [ ] 月末・週境界・日またぎ勤務の明細がそろっている。
- [ ] 深夜、時間外、休日の重複区間を確認した。
- [ ] 適用制度に応じた上限時間を別工程で検査した。
- [ ] 時給改定日と手当の適用期間を確認した。
- [ ] 丸めの単位と方法が承認済みの規程に一致する。
- [ ] 給与取込の件数、金額、取込済み識別子を照合した。
- [ ] 未解決の警告に担当者、理由、期限がある。
- [ ] 入力、設定、結果、承認記録から再計算できる。

監査の締めくくりには、正常な日だけでなく、休憩不足、売上ゼロ、予測混在、日またぎを含む日を抽出する。警告が出るべき入力で停止し、修正後に必要な工程だけが再開できることを確認する。この往復まで検証しておくと、日々の運用で異常が起きても、原因の特定から訂正と承認までを同じ手順で進められる。
