# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

月次処理の目的は、計算時間を短くするだけではない。入力の欠落、二重取込、残高の断絶を、担当者が意思決定する前に止めることである。本章では、Python標準ライブラリだけを使い、検算、公開、日次警告、監査記録を組み合わせる。

金額は整数円で保存し、年月は `YYYY-MM` に統一する。第6章と同じく、対象は運転口座であり、`tax_reserve_outflow` は納税専用口座への振替である。金額欄に桁区切り、通貨記号、空欄、小数を許可しない。表示用の万円換算は、検算を通過した後で行う。

## 7.1 入力契約を先に決める

入力ファイルはUTF-8のCSVとし、ヘッダーを次の順序に固定する。

```csv
month_id,opening_cash,cash_inflow,fixed_outflow,variable_outflow,tax_reserve_outflow,closing_cash
2027-04,4000000,1800000,1500000,1600000,200000,2500000
2027-05,2500000,1600000,1500000,1800000,200000,600000
```

この例は書式説明用の2行である。以下の月次バッチは、12か月分そろっていなければ公開しない。

入金と各支出は非負の整数とする。返品や返金は、相殺して負の入金にするのではなく、資金の方向に合った明細へ分類してから集計する。月初・月末残高には負数を許し、資金不足を示す予測を保持する。ただし、実績に負数が出た場合は、当座貸越等の扱いを含めて別途確認する。

12行あるだけでは、正しい12か月とは限らない。同じ月の重複、途中月の欠落、対象開始月のずれをすべて検出する。最初の月初残高については、銀行照合済み残高など、CSVとは別に確認した値を渡す。

## 7.2 12か月の検算と安全な公開

次のコードは `monthly_check.py` として保存する。入力をすべて検査した後に、一時ファイルを同じディレクトリへ書き込み、完成したファイルへ置き換える。エラーがあれば既存の公開ファイルは変更しない。

```python
import csv
import hashlib
import io
import json
import os
import re
import sys
import tempfile
from datetime import date, datetime, timezone
from pathlib import Path

FIELDS = (
    "month_id", "opening_cash", "cash_inflow",
    "fixed_outflow", "variable_outflow",
    "tax_reserve_outflow", "closing_cash",
)

def integer(text):
    if not isinstance(text, str):
        raise ValueError("金額がありません")
    if not re.fuテキスト処理系atch(r"-?(0|[1-9][0-9]*)", text):
        raise ValueError(f"整数円ではありません: {text!r}")
    return int(text)

def month_number(text):
    if not re.fuテキスト処理系atch(r"[0-9]{4}-(0[1-9]|1[0-2])", text):
        raise ValueError(f"年月形式が不正です: {text!r}")
    year, month = map(int, text.split("-"))
    date(year, month, 1)
    return year * 12 + month - 1

def validate(raw, start, opening):
    stream = io.StringIO(raw.decode("utf-8-sig"), newline="")
    reader = csv.DictReader(stream)
    if reader.fieldnames != list(FIELDS):
        raise ValueError("ヘッダーが仕様と一致しません")

    rows = list(reader)
    if len(rows) != 12:
        raise ValueError("12か月分のデータが必要です")

    first = month_number(start)
    expected_opening = opening
    minimum = None
    minimum_month = None

    for index, row in enumerate(rows):
        if set(row) != set(FIELDS) or any(
            value is None for value in row.values()
        ):
            raise ValueError(f"{index + 2}行目の列数が不正です")

        month = row["month_id"]
        if month_number(month) != first + index:
            raise ValueError(f"{month}: 月の順序または連続性が不正です")

        values = {key: integer(row[key]) for key in FIELDS[1:]}
        if any(values[key] < 0 for key in FIELDS[2:6]):
            raise ValueError(f"{month}: 入出金額が負数です")
        if values["opening_cash"] != expected_opening:
            raise ValueError(f"{month}: 月初残高が一致しません")

        calculated = (
            values["opening_cash"] + values["cash_inflow"]
            - values["fixed_outflow"] - values["variable_outflow"]
            - values["tax_reserve_outflow"]
        )
        if values["closing_cash"] != calculated:
            raise ValueError(f"{month}: 月末残高の検算不一致")

        expected_opening = calculated
        if minimum is None or calculated < minimum:
            minimum = calculated
            minimum_month = month

    return rows, minimum, minimum_month

def publish(path, rows):
    path.parent.mkdir(parents=True, exist_ok=True)
    temporary = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", newline="",
            dir=path.parent, delete=False
        ) as handle:
            temporary = Path(handle.name)
            writer = csv.DictWriter(handle, fieldnames=FIELDS)
            writer.writeheader()
            writer.writerows(rows)
            handle.flush()
            os.fsync(handle.fileno())
        os.replace(temporary, path)
    finally:
        if temporary is not None:
            temporary.unlink(missing_ok=True)

def main():
    if len(sys.argv) != 6:
        raise ValueError(
            "引数: 入力CSV 出力CSV 開始月 確認済み月初残高 警戒額"
        )

    source, destination, start, opening, floor = sys.argv[1:]
    source_path = Path(source)
    destination_path = Path(destination)
    if source_path.resolve() == destination_path.resolve():
        raise ValueError("入力と出力は別のファイルにしてください")

    floor = integer(floor)
    if floor < 0:
        raise ValueError("警戒額は非負で指定してください")

    raw = source_path.read_bytes()
    rows, minimum, month = validate(raw, start, integer(opening))
    publish(destination_path, rows)
    print(json.dumps({
        "status": "warning" if minimum < floor else "ok",
        "checked_at": datetime.now(timezone.utc).isoformat(),
        "input_sha256": hashlib.sha256(raw).hexdigest(),
        "start_month": start,
        "minimum_month": month,
        "minimum_cash": minimum,
        "cash_floor": floor,
        "output": str(destination_path),
    }, ensure_ascii=False))

if __name__ == "__main__":
    try:
        main()
    except (OSError, ValueError, csv.Error) as error:
        print(f"検算停止: {error}", file=sys.stderr)
        sys.exit(1)
```

この処理は、誤った `closing_cash` を黙って書き換えない。元データとの不一致を残して停止するため、入力の訂正理由を追える。金額を計算する工程と、その計算を検査する工程を分けることが、運用上の要点である。

また、警戒額未満の予測は計算不良ではない。検算に合格したうえで `warning` を返し、資金対策の対象として扱う。エラーと資金警告を同じ停止状態にすると、危険な予測ほど公開されないという逆転が起きる。

## 7.3 バッチ連携と再実行の扱い

月次バッチは「明細取込→月次集計→検算→公開→担当者への通知」の順にする。検算プログラムの終了コードがゼロの場合だけ、公開後の処理へ進める。実行例は次のとおりである。

```text
python3 monthly_check.py input.csv published.csv 2027-04 4000000 1000000
```

連携元もPythonで書く場合は、シェルを介さずに引数を渡せる。

```python
import json
import subprocess
import sys

result = subprocess.run(
    [
        sys.executable, "monthly_check.py",
        "input.csv", "published.csv",
        "2027-04", "4000000", "1000000",
    ],
    capture_output=True,
    text=True,
    check=True,
)
receipt = json.loads(result.stdout)
if receipt["status"] == "warning":
    print("資金警告:", receipt["minimum_month"])
```

実運用では、入力、出力、プログラムを絶対パスで指定する。標準出力の受付記録と標準エラーを、実行単位で保存する。終了コードがゼロ以外なら、古い公開ファイルを「今回更新済み」と表示してはいけない。画面や帳票に最終成功日時を出し、更新失敗を別途通知する。

入力ファイルは取込完了後に確定名へ変更し、書込み途中のものを読み込ませない。実行管理側では同時起動数を一つに制限する。ファイル置換は途中状態の露出を抑えるが、古い処理が新しい結果を上書きする競合までは防がない。

日次明細の取込では、銀行の取引識別子などを重複判定に使う。同じ日付・同じ金額の正当な取引が存在するため、この二項目だけで重複を削除しない。再実行時は明細へ追加し続ける方式を避け、確定した入力集合から集計し直す。

受付記録のハッシュ値は、使用した入力の同一性を調べるためのものである。元データが正しいことや、承認済みであることまでは証明しない。入力原本、承認記録、プログラムの版を組み合わせて保管する。

## 7.4 日次最低残高を求める応用

月次検算に合格しても、月中の不足は残る。次の関数は、同日内の入出金順序が未確認の場合に、支出を先に置いた保守的な最低残高を求める。`events` は、対象期間の入金と支出を整数円で集計した明細である。

```python
from collections import defaultdict
from datetime import date

def daily_lowest(opening, events):
    totals = defaultdict(lambda: [0, 0])
    for item in events:
        day = date.fromisoformat(item["date"])
        incoming = item["inflow"]
        outgoing = item["outflow"]
        if (
            type(incoming) is not int
            or type(outgoing) is not int
            or incoming < 0
            or outgoing < 0
        ):
            raise ValueError("日次入出金は非負の整数円で指定します")
        totals[day][0] += incoming
        totals[day][1] += outgoing

    balance = opening
    lowest = opening
    lowest_day = None
    for day in sorted(totals):
        incoming, outgoing = totals[day]
        before_receipt = balance - outgoing
        if before_receipt < lowest:
            lowest = before_receipt
            lowest_day = day.isoformat()
        balance = before_receipt + incoming

    return {
        "closing_cash": balance,
        "lowest_cash": lowest,
        "lowest_date": lowest_day,
    }
```

この値は、時刻まで確認した実残高推移ではなく、同日入金を待たずに支払う場合の下限予測である。着金時刻と引落時刻を確定できる取引は、順序を持つ別明細で精密化する。最低残高が月初残高のままなら、`lowest_date` は空値となる。

日次明細には、納税振替、借入、返済、手数料も含める。月内の日次入出金合計が月次表と一致し、日次計算の最終残高が `closing_cash` と一致することを確認する。日次だけ別の対象口座にすると、この照合は成立しない。

## 7.5 実務監査チェックリスト

監査では、式の正しさに加えて、入力の根拠と処理の継続性を確認する。担当者のチェック記号だけで終わらせず、照合資料、確認日時、差異の処置を残す。

| 確認対象 | 合格条件 | 保存する証跡 |
|---|---|---|
| 対象範囲 | 対象口座と除外口座が明確 | 口座一覧と集計方針 |
| 初月残高 | 独立に確認した残高と一致 | 基準日時付き銀行明細 |
| 月の連続性 | 指定開始月から12か月連続 | 検算受付記録 |
| 入金予定 | 請求額と回収条件に対応 | 請求明細と変更履歴 |
| 支払予定 | 支払日と金額に根拠がある | 契約・請求・給与資料 |
| 納税振替 | 元口座と先口座が対応 | 両口座の振替明細 |
| 納付予定 | 税目、日付、予定額が確認済み | 確認資料と確認者 |
| 月内不足 | 最低残高と発生日を確認 | 日次予測と対策記録 |
| 再実行 | 同じ入力で重複計上しない | 入力識別子と実行履歴 |
| 公開状態 | 最新成功日時と対象月が明確 | 公開版と受付記録 |

日次では、銀行の実績を取り込み、予定との差を金額差、日付差、未登録取引に分ける。予定を消して実績へ置き換えるだけでは、予測精度の改善に使える情報が失われる。元の予定日と予定額も保持する。

月次では、締めた実績月を固定し、翌月以降を再予測する。実績確定後に訂正した場合は、訂正前の版を残して再公開する。借入の実行予定や支払延期は、承認・合意の状態を確認し、未確定の対策を基本予測へ混ぜない。

稼働前には、少なくとも「月の欠落」「月初残高の不一致」「月末計算の誤り」「正しく計算された資金不足」を試す。最初の三つは公開停止、最後の一つは公開と警告になることを確認する。さらに同じ入力の再実行で結果が変わらないことを確かめる。

公開処理の成功と通知の成功は、別々に記録する。通知だけ失敗した場合は、取込や集計を重ねず、保存済みの受付記録から通知を再試行する。復旧訓練では、最後に成功した入力とプログラムの版から同じ結果を再現できるところまで確認する。
