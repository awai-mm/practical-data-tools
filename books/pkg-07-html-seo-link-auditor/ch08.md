# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

日々の検品を安定させるには、検査の速さよりも、入力と判定が毎回同じになることが重要である。担当者の記憶に頼らず、対象一覧、検査規則、結果ファイル、終了コードを一つの運用として定義する。本章では、Python標準ライブラリで保存済みHTMLを検査し、必須八カラムのCSVを出力する構成を示す。

## 7.1 入力一覧を検査対象の正本にする

検査対象をディレクトリ内のHTML検索だけで決めると、成果物から消えたページを見落とす。そこで、公開予定ページの一覧を`pages.csv`として管理する。検査対象が欠けていれば、読み込みエラーとして停止できる。

```csv
page_id,url_path,html_file
lp-001,/service/a/,service/a/index.html
lp-002,/service/b/,service/b/index.html
lp-003,/contact/,contact/index.html
```

`html_file`は成果物ディレクトリからの相対パスとし、CSV出力には含めない。`page_id`と`url_path`の重複は入力エラーにする。文字コードはUTF-8に統一し、読み込み時に不正なバイトを置き換えない。壊れた入力を黙って処理すると、文字数や説明文の欠落を誤判定するためである。

以下の実装は、保存済みHTMLの静的検査を対象とする。ブラウザ内で後から追加される要素、画像の表示内容、外部URLの応答は検査しない。動的なページでは、別工程で取得した描画後のHTMLも検査対象にする。

## 7.2 HTMLを解析して八カラムを作る

次のコードを`audit.py`として保存する。例示ドメインはURLのホスト名で判定し、本文に文字列が含まれるだけでは仮リンクに数えない。

```python
import csv
import os
import sys
import tempfile
from html.parser import HTMLParser
from pathlib import Path
from urllib.parse import urlsplit

FIELDS = [
    "page_id", "url_path", "title_length",
    "meta_desc_length", "h1_count",
    "missing_alt_count", "dummy_link_count",
    "ogp_complete",
]
OG_KEYS = {"og:title", "og:type", "og:url", "og:image"}


def is_dummy(value):
    value = value.strip()
    if value in {"", "#"}:
        return True
    try:
        host = (urlsplit(value).hostname or "").lower()
    except ValueError:
        return True
    host = host.rstrip(".")
    return host == "example.com" or host.endswith(".example.com")


class PageParser(HTMLParser):
    def __init__(self):
        super().__init__(convert_charrefs=True)
        self.titles = []
        self.in_title = False
        self.descriptions = []
        self.og = {}
        self.h1_count = 0
        self.missing_alt_count = 0
        self.dummy_link_count = 0

    def handle_starttag(self, tag, attrs):
        values = dict(attrs)
        if tag == "title":
            self.titles.append("")
            self.in_title = True
        elif tag == "h1":
            self.h1_count += 1
        elif tag == "img" and "alt" not in values:
            self.missing_alt_count += 1
        elif tag == "a" and "href" in values:
            if is_dummy(values["href"] or ""):
                self.dummy_link_count += 1
        elif tag == "meta":
            name = (values.get("name") or "").strip().lower()
            prop = (values.get("property") or "").strip().lower()
            content = (values.get("content") or "").strip()
            if name == "description":
                self.descriptions.append(content)
            if prop in OG_KEYS:
                self.og.setdefault(prop, []).append(content)

    def handle_endtag(self, tag):
        if tag == "title":
            self.in_title = False

    def handle_data(self, data):
        if self.in_title:
            self.titles[-1] += data

    def make_row(self, page_id, url_path):
        title = self.titles[0].strip() if self.titles else ""
        desc = self.descriptions[0] if self.descriptions else ""
        complete = all(
            any(self.og.get(key, [])) for key in OG_KEYS
        )
        return {
            "page_id": page_id,
            "url_path": url_path,
            "title_length": len(title),
            "meta_desc_length": len(desc),
            "h1_count": self.h1_count,
            "missing_alt_count": self.missing_alt_count,
            "dummy_link_count": self.dummy_link_count,
            "ogp_complete": "true" if complete else "false",
        }
```

空のhrefは仮リンクに含めるが、href属性のないa要素は数えない。リンクとして使うべき要素が操作できない問題は、別の操作確認で扱う。`#section`もこの関数では仮リンクとしないため、参照先IDが存在するかを別途検査する必要がある。

`ogp_complete`は四項目に非空の値があるかだけを表す。重複タグがあっても値が入っていればtrueになるため、次の判定処理で重複を別途検出する。属性があるだけの`alt`や空のaltについても、欠落件数とは分けて確認する。

## 7.3 判定と安全なCSV出力を追加する

次のコードを同じファイルへ続けて記述する。正常終了を0、品質基準への不適合を1、入力や実行の不備を2とする。これにより、制作物の修正と検査環境の修正を振り分けられる。

```python
def problems(parser, row):
    found = []
    if len(parser.titles) != 1:
        found.append("titleの個数")
    if len(parser.descriptions) != 1:
        found.append("descriptionの個数")
    if not 1 <= row["title_length"] <= 35:
        found.append("titleの文字数")
    if not 1 <= row["meta_desc_length"] <= 120:
        found.append("descriptionの文字数")
    if row["h1_count"] != 1:
        found.append("h1の個数")
    if row["missing_alt_count"]:
        found.append("alt属性の欠落")
    if row["dummy_link_count"]:
        found.append("仮リンク")
    if row["ogp_complete"] != "true":
        found.append("OGPの不足")
    if any(len(v) > 1 for v in parser.og.values()):
        found.append("OGPの重複")
    return found


def write_csv(target, rows):
    target.parent.mkdir(parents=True, exist_ok=True)
    temp_path = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", newline="",
            dir=target.parent, delete=False,
        ) as stream:
            temp_path = Path(stream.name)
            writer = csv.DictWriter(stream, fieldnames=FIELDS)
            writer.writeheader()
            writer.writerows(rows)
        os.replace(temp_path, target)
    finally:
        if temp_path is not None:
            temp_path.unlink(missing_ok=True)


def run(manifest, root, target):
    root = root.resolve()
    rows = []
    seen_ids = set()
    seen_paths = set()
    has_problems = False

    with manifest.open(encoding="utf-8-sig", newline="") as stream:
        reader = csv.DictReader(stream)
        required = {"page_id", "url_path", "html_file"}
        if not required <= set(reader.fieldnames or []):
            raise ValueError("入力一覧の必須列が不足しています")

        for item in reader:
            page_id = (item.get("page_id") or "").strip()
            url_path = (item.get("url_path") or "").strip()
            source = (item.get("html_file") or "").strip()
            if not page_id or not url_path or not source:
                raise ValueError("入力一覧に空欄があります")
            if page_id in seen_ids or url_path in seen_paths:
                raise ValueError("入力一覧に重複があります")
            if not url_path.startswith("/") or url_path.startswith("//"):
                raise ValueError("公開パスの形式を確認してください")

            path = (root / source).resolve()
            if not path.is_relative_to(root):
                raise ValueError("成果物の外側は検査できません")

            parser = PageParser()
            parser.feed(path.read_text(encoding="utf-8"))
            parser.close()
            row = parser.make_row(page_id, url_path)
            found = problems(parser, row)
            if found:
                has_problems = True
                print(page_id + ": " + "、".join(found),
                      file=sys.stderr)

            rows.append(row)
            seen_ids.add(page_id)
            seen_paths.add(url_path)

    if not rows:
        raise ValueError("検査対象がありません")
    write_csv(target, rows)
    return 1 if has_problems else 0


if __name__ == "__main__":
    try:
        if len(sys.argv) != 4:
            raise ValueError(
                "使い方: python3 audit.py pages.csv dist result.csv"
            )
        status = run(*(Path(value) for value in sys.argv[1:]))
    except (OSError, UnicodeError, ValueError, csv.Error) as exc:
        print("検査を完了できませんでした: " + str(exc),
              file=sys.stderr)
        status = 2
    sys.exit(status)
```

Python 3.9以降を想定している。出力先と同じディレクトリに一時ファイルを置き、書き込み完了後に置き換えるため、途中までのCSVが正式結果として読まれるリスクを減らせる。ただし、停止時に以前の結果が残る可能性はある。実行ごとに別の出力先を使い、終了コードと組み合わせて読む必要がある。

このパーサーはブラウザのDOM構築を完全には再現しない。壊れたHTMLの修復結果や要素の配置妥当性まで保証するものではなく、HTML構文の検証は補助工程として追加する。

## 7.4 日次バッチへ接続する

日次処理では、成果物を確定させてから検査し、検査中に対象ファイルを書き換えない。実行用ディレクトリには日時だけでなく一意な識別子を付け、同時実行でも結果が混ざらないようにする。

```python
import subprocess
import sys
from datetime import datetime, timezone
from pathlib import Path
from uuid import uuid4

stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
folder = Path("reports") / (stamp + "-" + uuid4().hex[:8])
folder.mkdir(parents=True)
result = folder / "result.csv"

try:
    with (folder / "audit.log").open(
        "w", encoding="utf-8"
    ) as log:
        process = subprocess.run(
            [
                sys.executable, "audit.py",
                "pages.csv", "dist", str(result),
            ],
            stdout=log,
            stderr=subprocess.STDOUT,
            timeout=300,
            check=False,
        )
    status = process.returncode
    if status not in {0, 1, 2}:
        status = 2
except (OSError, subprocess.TimeoutExpired):
    status = 2

(folder / "status.txt").write_text(
    str(status) + "\n", encoding="utf-8"
)
sys.exit(status)
```

スケジューラーからこの処理を呼び出し、0なら合格、1なら制作担当者の確認待ち、2なら運用担当者の調査待ちにする。結果ファイルが存在するだけで公開を許可してはいけない。実行識別子、終了コード、対象件数の三つを確認する。

監査結果には成果物の識別情報と規則の版も添付する。公開工程は検査済みの成果物をそのまま受け取り、途中で再構築した場合は再検査する。公開後には、主要URLから取得した内容と主要導線を確認する工程を設ける。

## 7.5 月次集計と表記揺れ検査の拡張

月次では、指摘総数に加えて不適合ページ率を集計する。分母は検査を完了したページ数とし、取得失敗や読み込み失敗は別に記録する。100ページ中10ページの不適合と、20ページ中10ページの不適合では改善判断が変わる。

前回との比較は`page_id`をキーにする。新規ページ、削除ページ、継続ページを分け、対象が増えただけなのに品質が低下したと判断しない。規則を変更した月は変更前後をそのまま比較せず、同じ規則で再集計するか、集計条件の違いを明記する。

表記揺れは承認済み辞書から候補を抽出する。HTMLソース全体を単純置換するとURLや属性まで壊すため、検査対象は抽出した本文に限定する。候補の扱いは次のように分ける。

| 候補 | 推奨表記 | 確認事項 |
|---|---|---|
| お問合せ | お問い合わせ | 引用部分を除外する |
| 申込み | 申し込み | 固有の商品名を確認する |
| WEB | Web | ブランド表記の例外を確認する |

辞書には適用範囲、例外、承認日を持たせる。件数だけで担当者を評価せず、同じ部品から繰り返し発生している問題を優先して直す。

## 7.6 公開判定に使う監査チェックリスト

日次の確認では、機械判定の結果と人が確認する項目を併用する。

- [ ] 入力一覧と公開予定ページの件数が一致している。
- [ ] 未検査、読み込み失敗、時間切れが残っていない。
- [ ] 八カラムが規定順で出力され、真偽値の形式が統一されている。
- [ ] titleとdescriptionの重複、空文字、文字数を確認した。
- [ ] h1と見出し階層がページの内容に対応している。
- [ ] alt属性の欠落と、説明内容の適切さを別々に確認した。
- [ ] 仮リンク、ページ内参照、主要導線を確認した。
- [ ] OGPの値、公開URL、画像内容が一致している。
- [ ] 表記辞書の候補を文脈に沿って確認した。
- [ ] 公開対象が検査済み成果物と一致している。

月次には、期限切れの例外、繰り返す指摘、検査漏れのあったページ種別を確認する。規則を追加した場合は、既知の正常例と異常例で判定を確かめる。最後に、担当者不在でもログから原因と次の作業を判断できるかを点検する。運用の品質は、検査件数よりも、異常を確実に止めて修正へつなげられるかで決まる。
