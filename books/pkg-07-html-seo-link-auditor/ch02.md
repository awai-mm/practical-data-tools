# 第1章 LP・Webページ公開直後に発覚する典型的な設定漏れ

**本章の焦点**：SNSシェア時のOGP事故とダミーリンク残存

---

## 1.1 実務における課題の整理と設計方針

title・description文字数超過、OGP未設定、h1複数混入・見出し階層飛ばし、alt属性漏れ、ダミーURL（#やexample.com）残存を公開前に一括検出する実務書＆監査ツール。

現場の業務フローにおいて、「SNSシェア時のOGP事故とダミーリンク残存」を曖昧なまま手作業で処理していると、担当者ごとの判断ブレや集計ミスが避けられません。本章では、入力データの構造を厳密に定義し、再現性のある検算・判定プロセスへ落とし込む手順を解説します。

### 標準入力カラム定義（主キー：`page_id`）

- `page_id`
- `url_path`
- `title_length`
- `meta_desc_length`
- `h1_count`
- `missing_alt_count`
- `dummy_link_count`
- `ogp_complete`

---

## 1.2 自動検証・計算機能（コアロジック）

本パッケージで提供するブラウザ版ワークベンチ（`html_seo_audit_workbench.html`）およびコマンドラインツール（`html_seo_audit_cli.py`）は、以下の機能を標準搭載しています。

1. **title/description文字数適正判定**
2. **h1重複・欠損検査**
3. **画像alt漏れ・ダミーリンク残存検出**
4. **公開可否監査レポート出力**

---

## 1.3 実践コマンドと運用チェックポイント

手元のCSVデータに対して一括検証と正規化を実行する場合は、以下のコマンドを使用します。

```bash
/usr/bin/python3 html_seo_audit_cli.py samples/problem_data.csv \
  --key page_id \
  --fix \
  --output-csv samples/verified_output.csv \
  --output-json samples/report.json
```

### 現場導入時の確認事項

| 確認フェーズ | 点検項目 | 合格基準 |
| :--- | :--- | :--- |
| **1. 入力データ受領時** | 必須カラム（全8列）の存在と主キー `page_id` の一意性 | 欠損列0件・重複キー0件 |
| **2. 数値・日付正規化** | 全角数字・カンマ・通貨記号・前後空白の除去 | 型変換エラー0件 |
| **3. 業務ロジック検算** | SNSシェア時のOGP事故とダミーリンク残存に関する閾値および計算整合性 | 指摘エラー0件（終了コード `0`） |
| **4. 証跡保存** | 修正前後の差分確認とJSONレポートの保管 | 月次フォルダへの保存完了 |
