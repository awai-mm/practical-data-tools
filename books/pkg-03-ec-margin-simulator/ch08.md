# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

収支計算を日常運用へ組み込む際は、計算速度よりも「異常な入力を止める」「同じ入力から同じ結果を得る」「訂正の経緯を残す」の3点を優先する。誤ったデータを毎朝高速に配信する仕組みは、手作業よりも広い範囲へ判断ミスを伝えてしまう。

本章ではPython標準ライブラリだけを使う。対象は、1か月分のSKU・チャネル別CSVである。必須9カラムから基本限界利益を計算し、梱包材、返品、注文単位の固定手数料などは別工程で追加する。出力を最終利益と取り違えないよう、列名にも`basic`を付ける。

## 7.1 ファイルを受け取る前に契約を決める

入力ファイルはUTF-8で保存し、先頭の文字識別符号も許容する。金額は円単位で小数入力を認め、通貨記号と桁区切りは付けない。数量は0以上の整数、手数料率8%は`8`と記録する。

本レシピの1行は「対象月×SKU×チャネル」である。同じ商品を同じチャネルで複数価格で販売した場合は、値引き後売上を数量で割った平均単価を使う。原価、送料、広告費も同じ数量に対応する平均値とする。

ただし、平均単価と平均料率を別々に掛けても、実際の手数料に一致するとは限らない。月内で契約料率が変わる場合や、注文単位の固定額がある場合は、明細から実額を集計する追加工程が必要である。

| 検査対象 | 停止する条件 | 別途確認する条件 |
|---|---|---|
| ヘッダー | 必須列の欠落、重複列名 | 追加列の意味 |
| 識別子 | 空欄、同一キーの重複 | 新規チャネル |
| 金額 | 数値以外、非有限値、負値 | 前月からの急変 |
| 数量 | 負数、小数、空欄 | 0件、急増・急減 |
| 手数料率 | 0未満、100超 | 契約マスターとの差 |

費用の戻入などで負値が必要な場合は、通常売上ファイルへ混在させず、調整台帳へ記録する。値域が正しくても意味が誤っている可能性は残るため、契約照合や総額照合は省略できない。

## 7.2 応用レシピ：検証してから結果を公開する

次のコードを`profit_batch.py`として保存する。入力と出力は別ファイルとし、入力異常があれば既存の出力を更新しない。金額には二進浮動小数点数を使わず、`Decimal`を使う。

```python
import csv
import hashlib
import io
import os
import sys
import tempfile
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP
from pathlib import Path

FIELDS = (
    "sku_id", "item_name", "channel", "selling_price",
    "cost_of_goods", "shipping_cost", "fee_rate_pct",
    "ad_cost_per_unit", "monthly_units",
)
MONEY = (
    "selling_price", "cost_of_goods", "shipping_cost",
    "ad_cost_per_unit",
)
EXTRA = (
    "source_sha256", "unit_basic_margin",
    "month_basic_margin", "margin_status",
)

def number(value, label):
    try:
        result = Decimal(value)
    except InvalidOperation:
        raise ValueError(f"{label}: 数値ではありません")
    if not result.is_finite() or result < 0:
        raise ValueError(f"{label}: 有限の非負値が必要です")
    return result

def display(value):
    return str(value.quantize(
        Decimal("0.01"), rounding=ROUND_HALF_UP
    ))

def calculate(raw):
    digest = hashlib.sha256(raw).hexdigest()
    source = io.StringIO(raw.decode("utf-8-sig"), newline="")
    reader = csv.DictReader(source, strict=True)
    names = reader.fieldnames or []

    if len(names) != len(set(names)):
        raise ValueError("列名が重複しています")
    missing = set(FIELDS) - set(names)
    if missing:
        raise ValueError(f"必須列がありません: {sorted(missing)}")

    seen = set()
    output = []
    for row in reader:
        line = reader.line_num
        if None in row or any(v is None for v in row.values()):
            raise ValueError(f"{line}行: 列数が一致しません")
        values = {key: row[key].strip() for key in FIELDS}
        if any(not value for value in values.values()):
            raise ValueError(f"{line}行: 空欄があります")

        key = (values["sku_id"], values["channel"])
        if key in seen:
            raise ValueError(f"{line}行: キーが重複しています")
        seen.add(key)

        amounts = {
            key: number(values[key], f"{line}行 {key}")
            for key in MONEY
        }
        rate = number(values["fee_rate_pct"], f"{line}行 料率")
        if rate > 100:
            raise ValueError(f"{line}行: 料率が100を超えています")

        units_text = values["monthly_units"]
        if not units_text.isascii() or not units_text.isdigit():
            raise ValueError(f"{line}行: 数量は整数が必要です")
        units = int(units_text)

        price = amounts["selling_price"]
        margin = (
            price - amounts["cost_of_goods"]
            - amounts["shipping_cost"]
            - price * rate / Decimal("100")
            - amounts["ad_cost_per_unit"]
        )
        output.append({
            **values,
            "source_sha256": digest,
            "unit_basic_margin": display(margin),
            "month_basic_margin": display(margin * units),
            "margin_status": "要確認" if margin <= 0 else "正",
        })

    if not output:
        raise ValueError("明細がありません")
    return output

def publish(path, rows):
    temp_name = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", newline="",
            dir=path.parent, prefix=".profit-", delete=False,
        ) as stream:
            temp_name = stream.name
            writer = csv.DictWriter(
                stream, fieldnames=FIELDS + EXTRA
            )
            writer.writeheader()
            writer.writerows(rows)
            stream.flush()
            os.fsync(stream.fileno())
        os.replace(temp_name, path)
    finally:
        if temp_name and os.path.exists(temp_name):
            os.unlink(temp_name)

def run():
    if len(sys.argv) != 3:
        raise ValueError("入力CSVと出力CSVを指定してください")
    source = Path(sys.argv[1]).resolve()
    target = Path(sys.argv[2]).resolve()
    if source == target:
        raise ValueError("入力と出力は別ファイルにしてください")
    raw = source.read_bytes()
    rows = calculate(raw)
    publish(target, rows)
    print(f"完了: {len(rows)}行")

if __name__ == "__main__":
    try:
        run()
    except (ValueError, OSError, UnicodeError,
            csv.Error, InvalidOperation) as exc:
        print(f"処理停止: {exc}", file=sys.stderr)
        sys.exit(1)
```

このコードは入力を一度だけ読み、その内容から計算とハッシュ値の作成を行う。読み直しの間に元ファイルが更新され、結果と記録が食い違うことを避けるためである。

結果は出力先と同じディレクトリに一時保存し、書き込み完了後に置換する。これにより、読み手が途中まで書かれたCSVを参照する可能性を減らせる。ただし、同時実行の排他制御や、停電時の完全な永続性まで保証するものではない。

月間利益は丸め前の単価から計算する。表示した単価に数量を掛けると、表示上の端数差が生じる場合がある。実請求との照合には、契約どおりに明細単位または注文単位で丸めた手数料を使う。

## 7.3 応用レシピ：損益分岐点を「到達不能」と区別する

限界利益が0以下のとき、損益分岐販売数を0個と表示してはいけない。販売を増やしても正の固定費を回収できないため、数量では解決できない状態として扱う。

```python
from decimal import Decimal, ROUND_CEILING

def break_even(fixed_cost, unit_margin):
    fixed = Decimal(str(fixed_cost))
    margin = Decimal(str(unit_margin))
    if not fixed.is_finite() or not margin.is_finite():
        raise ValueError("有限の値が必要です")
    if fixed < 0:
        raise ValueError("固定費は非負値が必要です")
    if margin <= 0:
        return None
    return int((fixed / margin).to_integral_value(
        rounding=ROUND_CEILING
    ))
```

例えば固定費120,000円、限界利益126円なら953個となる。`None`は「数量による回収判定不可」と表示し、価格、原価、物流条件の見直し対象にする。

複数商品をまとめて計算する場合は、販売構成比で加重した限界利益を使う。その分岐点は構成比が維持されるという仮定付きである。固定費を商品へ配賦した場合は、全社集計で同じ固定費を再び控除しない。

## 7.4 日次・月次バッチの連携レシピ

日次処理は、受領、検証、計算、照合、公開の順に分ける。受領ファイルをそのまま公開場所に置かず、連携元から転送完了の通知または完了印を受けてから読み込む。更新時刻が古いという理由だけで、転送完了と判断しない。

処理対象は「対象月・基準日時・入力ハッシュ値・計算仕様の版」で識別する。同じ条件の再実行では結果を加算せず、同じ処理として扱う。訂正データは新しいハッシュ値と改訂番号で保存する。

連携プログラムからの呼び出しには、次の形を使える。

```python
import subprocess
import sys

def execute(script, source, target):
    result = subprocess.run(
        [sys.executable, str(script), str(source), str(target)],
        capture_output=True, text=True, timeout=300,
    )
    if result.returncode != 0:
        raise RuntimeError(result.stderr.strip())
    return result.stdout.strip()
```

パスは設定済みのものを渡し、計算結果は実行ごとの保存先へ出力する。正常終了だけで公開せず、売上、数量、送料、広告費の総額照合を通過した後に最新版への参照を切り替える。

日次入力が月初からの累計なら、前日結果へ足し込まない。累計スナップショットとして置き換える。月次では締め対象日と返品の基準日を固定し、確定版を保存する。締め後の訂正は旧版を残し、差額と訂正理由を記録する。

同じ出力先への並行実行は、実行管理側で禁止する。停止時に前回結果が残る設計では、利用者がそれを当日分と誤認し得るため、画面や帳票には対象期間、最終成功日時、最新処理の成否を表示する。

## 7.5 実務監査チェックリスト

監査では「処理が動いた証拠」と「数字が正しい証拠」を分けて確認する。

### 日次確認

- [ ] 必須9カラムが存在し、キー重複と空欄がない。
- [ ] 入力元の売上・販売数量と集計結果が一致する。
- [ ] 手数料率が有効日付きの契約マスターと一致する。
- [ ] 送料と梱包材の配賦前後で総額が一致する。
- [ ] 広告費の分母が購入件数か販売数量か明確である。
- [ ] 限界利益が0以下の行を担当者が確認している。
- [ ] 最終成功日時と当日の処理状態が利用者に見える。

### 月次確認

- [ ] 返品が元の販売明細へ結び付いている。
- [ ] 返金額、在庫回復額、返還手数料を二重計上していない。
- [ ] 売上と入金の差を未収、返金、手数料などで説明できる。
- [ ] 固定費の配賦総額が元帳と一致する。
- [ ] 基本限界利益に含まれない費用を追加反映している。
- [ ] 税込・税抜、通貨、締め時刻が統一されている。
- [ ] 未確定の返品見積もりと確定値を区別している。

### 訂正・復旧確認

- [ ] 入力原本、ハッシュ値、計算仕様の版を保存している。
- [ ] 異常入力で既存の公開結果が更新されない。
- [ ] 同じ入力の再実行で二重加算されない。
- [ ] 訂正前後の差額と影響範囲を説明できる。
- [ ] 失敗時の担当者、連絡先、復旧期限が決まっている。

導入時には、正常データに加え、重複行、空欄、非有限値、数量の小数、出力先への書き込み失敗を試す。計算式の正しさと同じ重さで、異常時に公開を止められることを確認する。日々の運用では、未解決の差額を持ち越す場合も、金額、理由、担当者、期限を記録し、説明できない数字を価格判断の根拠にしない。
