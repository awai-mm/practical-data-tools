# 第2章 売上・在庫・帳簿データの必須検品ルール12選

**本章の焦点**：主キー重複、必須列欠損、金額カンマ・通貨記号混入、日付フォーマット統一（YYYY-MM-DD）、数量×単価＝金額の検算、マイナス在庫・異常値の閾値設定

---

## 2.1 標準データスキーマと必須カラム定義

実務データの検品を自動化するにあたり、まず検査対象となる標準テーブル構造を定義します。本書および付属ツールでは、売上・在庫・帳簿のトランザクションデータとして以下の9カラムを基準スキーマ（必須列：`record_id`, `transaction_date`, `sku`, `item_name`, `category`, `quantity`, `unit_price`, `amount`, `stock_after`）として扱います。

| カラム名 | 論理名 | データ型・正規化後フォーマット | 検査の要点 |
| :--- | :--- | :--- | :--- |
| `record_id` | 伝票・明細ID | 文字列（一意・必須、例: `REC-1001`） | 空欄不可・ファイル内重複不可 |
| `transaction_date` | 取引日付 | 日付文字列（`YYYY-MM-DD` 形式） | 表記揺れを正規化・存在しない日付を拒否 |
| `sku` | 商品・勘定コード | 文字列（英数字・ハイフン、先頭ゼロ保持） | 前後空白の除去・空欄不可 |
| `item_name` | 品名・摘要 | 文字列（UTF-8） | 制御文字・連続空白の正規化 |
| `category` | 部門・カテゴリ | 文字列 | 集計軸として使用・未設定時は警告 |
| `quantity` | 数量 | 整数（1以上を原則、返品時は明示） | 全角数字・カンマ除去、0以下は要確認 |
| `unit_price` | 単価 | 整数または小数（0以上） | 通貨記号（`¥`, `$`）・カンマ・空白の除去 |
| `amount` | 金額（小計） | 整数（`quantity * unit_price`） | 数量×単価との一致検算 |
| `stock_after` | 取引後在庫数 | 整数（0以上） | マイナス在庫（`< 0`）の即時検出 |

---

## 2.2 必須検品ルール12選（エラーレベルと自動修復可否）

現場で迷わないためには、検出した問題を**「自動クレンジングで安全に直せるもの（INFO / AUTO-FIX）」**と、**「担当者または元データ作成者に確認が必要な論理エラー（ERROR / WARNING）」**に明確に分ける必要があります。

### 【A】構造・識別子ルール
1. **`E01_MISSING_REQUIRED_COLUMN`（致命的エラー）**：必須カラムがヘッダに存在しない。
2. **`E02_EMPTY_PRIMARY_KEY`（エラー）**：主キー（`record_id`）が空欄である。
3. **`E03_DUPLICATE_PRIMARY_KEY`（エラー）**：同一の `record_id` が複数行に出現している（二重取り込みの危険）。

### 【B】表記揺れ・文字種ルール（自動クレンジング対象）
4. **`W04_WHITESPACE_PADDING`（自動修正）**：セルの前後または内部に不要な半角空白・全角空白・タブが含まれている。
5. **`W05_FULLWIDTH_NUMERIC`（自動修正）**：数値・日付・コード欄に全角数字（`０〜９`）や全角ハイフンが含まれている。
6. **`W06_CURRENCY_OR_COMMA_IN_NUMBER`（自動修正）**：金額・単価・数量に `,`（桁区切りカンマ）や `¥`・`円` が含まれている。
7. **`W07_DATE_FORMAT_VARIATION`（自動修正）**：`2026/10/5` や `2026.10.05` などの表記を `2026-10-05`（ISO 8601形式）へ統一する。

### 【C】型変換・妥当性ルール
8. **`E08_INVALID_DATE_VALUE`（エラー）**：`2026-02-30` や `2026-13-01` のようにカレンダー上存在しない日付、または解釈不能な文字列。
9. **`E09_NON_NUMERIC_VALUE`（エラー）**：クレンジング後も数値に変換できない文字（`未定`、`要確認`、`N/A` など）が数値列に入っている。

### 【D】業務ロジック・検算ルール
10. **`E10_AMOUNT_MISMATCH`（エラー）**：`quantity × unit_price` の計算結果と `amount` 列の値が一致しない（自動修正モードでは正値への再計算オプションを提供）。
11. **`E11_NEGATIVE_STOCK`（エラー）**：`stock_after`（取引後在庫）が `0` 未満（マイナス在庫）になっている。
12. **`W12_NON_POSITIVE_QUANTITY`（警告）**：`quantity` が `0` 以下になっている（赤伝・返品データでない限り入力ミスの可能性が高い）。

## 2.3 クレンジングパイプラインの実行順序

自動クレンジングと検算を組み合わせる場合、**必ず「文字の正規化 → 型変換 → 業務検算」の順番**で処理します。

```text
[生データ行の読込]
   │
   ├─ Step 1: 前後空白トリム & 制御文字除去 (W04)
   ├─ Step 2: 全角英数字・記号の半角正規化 NFKC相当 (W05)
   ├─ Step 3: 数値列の通貨記号・カンマ除去 (W06)
   ├─ Step 4: 日付文字列のパースと YYYY-MM-DD 統一 (W07 / E08)
   ├─ Step 5: 主キーの空欄・重複チェック (E02 / E03)
   └─ Step 6: 数量×単価＝金額検算 & マイナス在庫検査 (E10 / E11 / W12)
```

この順序を守ることで、「全角数字やカンマが入っていたせいで金額検算までエラーになる」といった二次エラーを完全に防ぎ、本当に人間が判断すべき論理エラーだけを浮かび上がらせることができます。
