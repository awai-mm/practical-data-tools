# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

日次運用では、異常を早く発見することが重要です。月次運用では、それに加えて「どの入力を、どのルールで処理し、何と照合して確定したか」を再現できなければなりません。

本章では、検品済みCSVを安全に集計・公開する処理を中心に、Python標準ライブラリだけで構成できる応用例を示します。コードは実行環境での検証を前提とする掲載例です。業務ごとの検品本体と組み合わせ、入出力の契約を明確にして運用してください。

## 7.1 入力を受け取る前に決める契約

必須カラムは次の九つです。

`record_id, transaction_date, sku, item_name, category, quantity, unit_price, amount, stock_after`

列名が揃っていても、値の意味が違えば安全に結合できません。最低限、数量の符号、単価の税込・税抜、金額の丸め、日付形式、キーの一意性、在庫残高の基準を決めます。

以下の例では、通貨を円に固定し、数量・単価・金額・在庫を整数とします。返品数量と返品金額は負、単価はゼロ以上、明細金額は数量と単価の積です。値引きや税計算でこの式が成立しないデータには、別の検査ルールが必要です。

日次の公開条件は「必須検査を通過した全行が揃うこと」とします。正常行だけを先に出す運用を採る場合は、部分出力であること、除外件数、後日の追加方法を別途定義してください。

## 7.2 数値の表記揺れを厳密に扱う

数値変換では、許す表記を列ごとに限定します。次の関数は全角数字と対応する記号を変換し、桁区切りの位置を確認してから十進数へ変換します。

```python
import re
from decimal import Decimal

TRANS = str.maketrans(
    "０１２３４５６７８９，．－＋",
    "0123456789,.-+",
)
NUMBER = re.compile(
    r"[+-]?(?:[0-9]+|[0-9]{1,3}(?:,[0-9]{3})+)"
    r"(?:\.[0-9]+)?"
)

def parse_number(raw, *, integer=False):
    value = raw.strip().translate(TRANS)
    if not NUMBER.fuテキスト処理系atch(value):
        raise ValueError("数値の形式が不正です")
    number = Decimal(value.replace(",", ""))
    if integer and number != number.to_integral_value():
        raise ValueError("整数ではありません")
    return number
```

`３,６００` は3600として受け付け、`36,00`、空欄、通貨記号付きの値は拒否します。整数指定では `3.0` を受け付けますが、`3.5` は拒否します。小数点そのものを禁止したい場合は、正規表現も整数専用にしてください。

この変換をSKUや伝票番号に流用してはいけません。`00123` を123にすると識別子が変わります。また、変換前の値は修正履歴へ保存し、正常化した値だけから元の状態を推測しないようにします。

金額に小数を許す場合は、精度の上限と丸める箇所も契約に含めます。計算途中の値を毎回丸める場合と、合計後に丸める場合では結果が異なります。

## 7.3 検品済みCSVを再検査して公開する

次の例は、前節の関数と同じファイルに置くコードです。検品済みCSVを再検査し、正規化CSVと集計レポートを一つのディレクトリにまとめます。前段の修正履歴や原票照合結果は、別途同じ実行番号にひも付けて保存します。

```python
import csv
import hashlib
import io
import json
import os
import shutil
import uuid
from datetime import date, datetime, timezone
from pathlib import Path

FIELDS = (
    "record_id transaction_date sku item_name category "
    "quantity unit_price amount stock_after"
).split()
NUMERIC = ("quantity", "unit_price", "amount", "stock_after")

def publish(source, output_root):
    source = Path(source)
    root = Path(output_root)
    root.mkdir(parents=True, exist_ok=True)

    data = source.read_bytes()
    digest = hashlib.sha256(data).hexdigest()
    stream = io.StringIO(data.decode("utf-8-sig"), newline="")
    reader = csv.DictReader(stream, strict=True)

    if reader.fieldnames != FIELDS:
        raise ValueError("列名または列順が契約と異なります")

    seen = set()
    rows = []
    total_quantity = 0
    total_amount = 0

    for row in reader:
        line = reader.line_num
        if None in row or any(v is None for v in row.values()):
            raise ValueError(f"{line}行付近: 列数が不正です")

        for key in FIELDS[:5]:
            if not row[key].strip() or row[key] != row[key].strip():
                raise ValueError(f"{line}行付近: {key}が不正です")

        record_id = row["record_id"]
        if record_id in seen:
            raise ValueError(f"{line}行付近: キーが重複しています")
        seen.add(record_id)

        day = row["transaction_date"]
        if date.fromisoformat(day).isoformat() != day:
            raise ValueError(f"{line}行付近: 日付形式が不正です")

        values = {
            key: int(parse_number(row[key], integer=True))
            for key in NUMERIC
        }
        if values["unit_price"] < 0:
            raise ValueError(f"{line}行付近: 単価が負です")
        if values["amount"] != values["quantity"] * values["unit_price"]:
            raise ValueError(f"{line}行付近: 金額が一致しません")
        if values["stock_after"] < 0:
            raise ValueError(f"{line}行付近: 在庫が負です")

        for key, value in values.items():
            row[key] = str(value)
        total_quantity += values["quantity"]
        total_amount += values["amount"]
        rows.append(row)

    if not rows:
        raise ValueError("明細がありません")

    run_id = uuid.uuid4().hex
    staging = root / f".working-{run_id}"
    destination = root / f"run-{run_id}"
    staging.mkdir()

    try:
        with (staging / "clean.csv").open(
            "w", encoding="utf-8", newline=""
        ) as handle:
            writer = csv.DictWriter(handle, fieldnames=FIELDS)
            writer.writeheader()
            writer.writerows(rows)

        report = {
            "run_id": run_id,
            "source_sha256": digest,
            "rule_version": "yen-integer-v1",
            "checked_at": datetime.now(timezone.utc).isoformat(),
            "row_count": len(rows),
            "quantity_total": total_quantity,
            "amount_total": total_amount,
        }
        (staging / "report.json").write_text(
            json.dumps(report, ensure_ascii=False, indent=2),
            encoding="utf-8",
        )
        os.rename(staging, destination)
    except Exception:
        shutil.rmtree(staging)
        raise

    return destination
```

検査中に例外が発生した場合、公開ディレクトリは作られません。出力中に失敗した場合も、作業用ディレクトリを削除して例外を上位へ返します。読み手は `run-` で始まる確定済みディレクトリだけを処理します。

二つのファイルを個別に公開すると、CSVだけが新しくレポートが古い状態が生まれます。ディレクトリ単位の切り替えは、その不一致を防ぐための設計です。

この方式は、同一ファイルシステム上でディレクトリ名の変更が原子的に扱われる環境を前提とします。ネットワーク共有では実際の動作を確認してください。また、これは電源断時の永続化まで保証する処理ではありません。

掲載例は全入力をメモリに保持します。大容量データでは、作業用CSVへ逐次出力し、重複キーを `sqlite3` の一意制約で管理する構成へ変更します。入力サイズと数値桁数にも上限を設け、過大なファイルを入口で止めてください。

## 7.4 日次バッチへ接続する

掲載例を `daily_job.py` として保存し、末尾に次を追加すると、入力ファイルと公開先を引数で受け取れます。

```python
if __name__ == "__main__":
    import sys

    try:
        if len(sys.argv) != 3:
            raise ValueError("入力CSVと公開先を指定してください")
        result = publish(sys.argv[1], sys.argv[2])
    except Exception as error:
        print(
            f"{type(error).__name__}: {error}",
            file=sys.stderr,
        )
        raise SystemExit(1)

    print(result)
```

起動側では、引数を文字列連結せずリストで渡します。

```python
import subprocess
import sys

result = subprocess.run(
    [
        sys.executable,
        "daily_job.py",
        "incoming/checked.csv",
        "published",
    ],
    check=True,
    capture_output=True,
    text=True,
    timeout=180,
)
published_directory = result.stdout.strip()
```

スケジューラには実運用の絶対パスを設定し、作業ディレクトリの違いによる読み間違いを避けます。`check=True` により、終了コードがゼロ以外なら後続処理へ進みません。タイムアウト時も成功として扱わず、公開済み成果物の有無を確認します。

入力元は書き込み中のファイルを渡さず、一時名で保存してから確定名へ変更します。受け取り側は確定名だけを対象にします。日付だけで「昨日のファイルが来たはず」と推測せず、対象期間と受領件数も確認してください。

## 7.5 再実行と月次締めを安全にする

このコードの重複検査は、一つのCSV内だけが対象です。同じ入力を再実行すると、別の実行番号で新しい成果物が作られます。取込先への二重登録を防ぐ仕組みは、別に必要です。

運用台帳には、入力ハッシュ、ルール版、対象期間、公開先、取込先のバッチ番号、処理状態を記録します。同一内容の再送は入力ハッシュで確認できますが、ファイルの並び替えや一部差し替えには明細キーの検査も必要です。

取り込みの応答が途切れたときは、再送より先に取込先の状態を照会します。取込先が一意な受付番号を受け付けるなら、再試行でも同じ番号を渡します。受け付けない場合は、照会と取消の手順を確定しておきます。

月次は日次ファイルを単純に足し合わせず、期間内の全件で重複キーを再検査します。遅れて届いた取引と訂正も扱うため、「取引日」と「受領日時」を分けて管理してください。締め直す場合は旧版を残し、新版への差額と変更理由を記録します。

## 7.6 実務監査チェックリスト

チェック欄だけを埋めず、根拠となるファイル、レポート、取込結果を実行番号でたどれる状態にします。

### 入力と正規化

- [ ] 元CSVを変更せず保存し、ハッシュを記録した。
- [ ] 必須列、列数、文字コード、引用符を検査した。
- [ ] 数量・単価・金額の意味と符号を確認した。
- [ ] 曖昧な日付や不正な桁区切りを推測で補正していない。
- [ ] 修正前後の値と適用ルールを保存した。
- [ ] 除外行と未解決行の件数を把握している。

### 集計と公開

- [ ] 件数・数量・金額を元資料と照合した。
- [ ] 日次内と月次全体の両方でキー重複を検査した。
- [ ] 金額一致の式と丸め方が業務契約に一致している。
- [ ] 在庫の検証範囲と、別台帳による確認範囲が明確である。
- [ ] CSVとレポートが同じ実行番号で公開されている。
- [ ] 中断時の作業ファイルを後続処理が読まない。

### 取り込みと締め

- [ ] 取込先の受付件数・金額を公開結果と照合した。
- [ ] 再実行前に前回の取り込み状態を確認した。
- [ ] 訂正・取消・締め直しの履歴を保存した。
- [ ] ルール版、実行環境、確認者を記録した。
- [ ] 保存期間と閲覧権限を定めた。
- [ ] 元CSVから成果物を再現する復旧手順を確認した。

日次担当者は受領から公開までを確認し、月次確認者は期間全体の照合と未解決事項を確認します。完了の判断は処理の正常終了だけでなく、入力、成果物、取込先の三者が一致していることを根拠にしてください。
