# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

日次集計を定着させるには、計算式よりも入出力の約束が重要になる。入力が欠けているのに成功扱いする、途中まで書いたファイルを後続処理が読む、再実行で二重計上する。この三つを防ぐだけでも、担当者の朝の確認作業は大きく減る。

本章では、ログから作成済みのCSVを検証し、日次成果物として公開し、月次集計へ接続する。七つの必須カラムを保持しながら、判定結果と集計条件を別の情報として添える構成にする。

## 7.1 入力契約を先に固定する

一つの入力CSVには一日分だけを格納し、`service_name`と`endpoint_id`の組を一意にする。時間帯別の行やサーバー別の行が残っている場合は、前段で統合する。ただしp95は各行の値を平均せず、元の処理時間または統合可能な分布情報から計算する。

| 項目 | このレシピの約束 |
|---|---|
| 対象期間 | UTCの00:00以上、翌日00:00未満 |
| 日付の所属 | 試行の終了時刻で決める |
| 文字コード | UTF-8、先頭のBOMは許容 |
| 件数 | 0以上の整数 |
| p95 | ミリ秒、有限の非負数 |
| 観測ゼロ | p95欄を空欄にする |
| 識別子 | 空欄と前後の空白を禁止 |
| 重複行 | 合算せず入力不備として停止 |

UTCを採用するのは、この例の実装を明確にするためである。業務日を日本時間で定義するなら、前段の抽出範囲から報告書の表示まで同じ基準へ変更する。ファイル名の日付だけを変えてはいけない。

タイムアウトは総リクエストの内数とし、5xxとの重複を許す。5xxと4xxの合計は総リクエスト以下でなければならない。この関係をコードで検証し、担当者の目視に依存させない。

## 7.2 検証と日次判定を一つの処理にまとめる

次の例を`daily_report.py`として保存する。引数は、対象日、入力CSV、出力JSONの順である。判定条件は説明用であり、サービスの通常値と業務上の許容範囲に合わせて変更する。

```python
import csv
import json
import math
import os
import sys
import tempfile
from datetime import date
from pathlib import Path

FIELDS = [
    "endpoint_id",
    "service_name",
    "total_requests",
    "error_5xx_count",
    "error_4xx_count",
    "p95_latency_ms",
    "timeout_count",
]
COUNTS = [
    "total_requests",
    "error_5xx_count",
    "error_4xx_count",
    "timeout_count",
]


def stop(message):
    sys.exit(message)


def read_rows(path):
    rows = []
    seen = set()

    with path.open(
        encoding="utf-8-sig", newline=""
    ) as source:
        reader = csv.DictReader(source, strict=True)
        names = reader.fieldnames

        if (
            names is None
            or len(names) != len(FIELDS)
            or set(names) != set(FIELDS)
        ):
            stop("ヘッダーが必須七列と一致しません")

        for raw in reader:
            position = reader.line_num
            if None in raw or any(
                value is None for value in raw.values()
            ):
                stop(f"{position}行目: 列数が不正です")

            row = dict(raw)
            for name in ("service_name", "endpoint_id"):
                value = row[name]
                if not value or value != value.strip():
                    stop(f"{position}行目: 識別子が不正です")

            key = (
                row["service_name"],
                row["endpoint_id"],
            )
            if key in seen:
                stop(f"{position}行目: 識別子が重複しています")
            seen.add(key)

            for name in COUNTS:
                value = row[name]
                if not (
                    value.isascii() and value.isdecimal()
                ):
                    stop(f"{position}行目: 件数が不正です")
                row[name] = int(value)

            total = row["total_requests"]
            errors = (
                row["error_5xx_count"]
                + row["error_4xx_count"]
            )
            if errors > total or row["timeout_count"] > total:
                stop(f"{position}行目: 件数の関係が不正です")

            value = row["p95_latency_ms"]
            if total == 0:
                if value != "":
                    stop(f"{position}行目: 観測ゼロのp95です")
                row["p95_latency_ms"] = None
            else:
                latency = float(value)
                if not math.isfinite(latency) or latency < 0:
                    stop(f"{position}行目: p95が不正です")
                row["p95_latency_ms"] = latency

            rows.append(row)

    if not rows:
        stop("データ行がありません")
    return rows


def evaluate(row):
    total = row["total_requests"]
    if total == 0:
        return ["観測ゼロ"]

    notes = []
    if (
        row["error_5xx_count"] >= 20
        and row["error_5xx_count"] / total >= 0.02
    ):
        notes.append("5xx率上昇")
    if total >= 100 and row["p95_latency_ms"] >= 1000:
        notes.append("応答時間超過")
    if (
        row["timeout_count"] >= 10
        and row["timeout_count"] / total >= 0.01
    ):
        notes.append("タイムアウト増加")
    return notes


def publish(path, document):
    path.parent.mkdir(parents=True, exist_ok=True)
    temporary = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w",
            encoding="utf-8",
            dir=path.parent,
            prefix=f".{path.name}.",
            delete=False,
        ) as stream:
            temporary = Path(stream.name)
            json.dump(
                document,
                stream,
                ensure_ascii=False,
                allow_nan=False,
                indent=2,
            )
            stream.write("\n")
            stream.flush()
            os.fsync(stream.fileno())
        os.replace(temporary, path)
        temporary = None
    finally:
        if temporary is not None:
            temporary.unlink(missing_ok=True)


def main():
    if len(sys.argv) != 4:
        stop("引数: 対象日 入力CSV 出力JSON")

    target = date.fromisoformat(sys.argv[1]).isoformat()
    rows = read_rows(Path(sys.argv[2]))
    alerts = []

    for row in rows:
        notes = evaluate(row)
        if notes:
            alerts.append({
                "service_name": row["service_name"],
                "endpoint_id": row["endpoint_id"],
                "reasons": notes,
            })

    publish(Path(sys.argv[3]), {
        "schema_version": 1,
        "rule_version": "2026-10",
        "target_date": target,
        "timezone": "UTC",
        "rows": rows,
        "alerts": alerts,
    })


if __name__ == "__main__":
    try:
        main()
    except (OSError, ValueError, csv.Error) as error:
        stop(f"処理を停止しました: {error}")
```

この処理は、不正行を読み飛ばさない。読み飛ばすと、異常が多い行だけが欠けた「正常な報告」を作るおそれがある。入力不備は非ゼロの終了コードで知らせ、既存の公開済み成果物は更新しない。

一時ファイルを出力先と同じディレクトリに作り、検証と書き込みが終わってから置き換える。これにより、後続処理が書きかけのJSONを読む危険を抑えられる。ただし、同じ対象日の並行実行は防げないため、スケジューラー側で同時実行数を1に制限する。停電時まで含めた永続性は、ファイルシステムの保証を別途確認する。

また、CSV自体には対象日時がない。このコードだけでは対象日の正しさを検証できないため、前段の抽出処理が対象期間と完了状態を記した実行記録を残す必要がある。

## 7.3 バッチ連携は「計算成功」と「異常あり」を分ける

異常を検出したことと、集計に失敗したことは別の状態である。この例では、異常があっても正しい成果物を書ければ終了コードは0になる。後続処理は`alerts`を読んで通知の要否を判断する。

| 段階 | 開始条件 | 完了条件 |
|---|---|---|
| ログ確定 | 対象期間が終了 | 遅着分を含む回収が完了 |
| CSV集計 | 回収記録を確認 | 七列と集計対象を確定 |
| 日次検証 | CSV書き込み完了 | 日付別JSONを公開 |
| 通知 | 日次検証が成功 | 通知結果を別記録へ保存 |
| 月次集計 | 全対象日の公開完了 | 欠日検査を通過 |

実行引数の例は、`2026-10-27 input/2026-10-27.csv daily/2026-10-27.json`となる。対象日を実行時刻から暗黙に決めず、スケジューラーから明示的に渡す。深夜の遅延や過去日の再処理でも、同じ入力契約を使える。

再実行では同じ日付の成果物を置き換え、月次処理は毎回日次成果物から計算し直す。追記方式は避け、再実行による二重加算を防ぐ。訂正履歴が必要なら、置換前の成果物と入力のハッシュ値を別の保管先へ残す。

通知の重複抑止には、対象日、サービス、エンドポイント、判定規則の版を組み合わせた識別子を使う。送信済み記録は通知が成功してから保存する。通知に失敗しても日次集計をやり直さず、公開済み成果物から通知だけを再試行する。

## 7.4 月次は件数を合計し、p95の意味を変えない

月次5xx率は、日次率の平均ではなく、月間5xx件数を月間総リクエスト数で割る。100件の日と100万件の日を同じ重みで扱わないためである。

一方、日次p95から月間p95は復元できない。次の例は件数の合計と「日次p95の最大値」を返す。関数は、前節と同じ検証済み形式の日次成果物を入力とする。

```python
import calendar
import json
from datetime import date
from pathlib import Path


def monthly(folder, year, month):
    groups = {}
    last_day = calendar.monthrange(year, month)[1]

    for day in range(1, last_day + 1):
        target = date(year, month, day).isoformat()
        path = Path(folder) / f"{target}.json"

        with path.open(encoding="utf-8") as stream:
            report = json.load(stream)

        if (
            report["target_date"] != target
            or report["schema_version"] != 1
            or report["timezone"] != "UTC"
        ):
            sys.exit(f"日次成果物の条件が不一致: {target}")

        for row in report["rows"]:
            key = (
                row["service_name"],
                row["endpoint_id"],
            )
            item = groups.setdefault(key, {
                "service_name": key[0],
                "endpoint_id": key[1],
                "total_requests": 0,
                "error_5xx_count": 0,
                "error_4xx_count": 0,
                "timeout_count": 0,
                "observed_days": 0,
                "max_daily_p95_latency_ms": None,
            })

            item["observed_days"] += 1
            for name in COUNTS:
                item[name] += row[name]

            latency = row["p95_latency_ms"]
            previous = item["max_daily_p95_latency_ms"]
            if latency is not None:
                item["max_daily_p95_latency_ms"] = (
                    latency if previous is None
                    else max(previous, latency)
                )

    return list(groups.values())
```

この断片は前節の`COUNTS`と`sys`を利用する。月途中の速報にはそのまま使わず、確定月だけを対象にする。日次ファイルが一つでも欠ければ例外で停止するため、欠日をゼロ件として月報へ混ぜずに済む。

ただし、ファイルの存在は、全エンドポイントの存在を保証しない。稼働開始日と終了日を含む台帳に照らし、`observed_days`を確認する。毎日稼働する対象は、観測ゼロの日も行を出す運用にする。

月次結果は日次の七列形式とは別の帳票である。`max_daily_p95_latency_ms`を`p95_latency_ms`へ改名して流用してはいけない。月間p95が必要なら、月内の元データから別途算出する。

## 7.5 実務監査チェックリスト

監査では「処理が動いたか」より、「その数字を信頼できる根拠が残っているか」を確認する。

| 頻度 | 確認項目 | 保存する証跡 |
|---|---|---|
| 日次 | 対象期間と時刻基準が一致したか | 抽出開始・終了時刻 |
| 日次 | ローテーション後のログも回収したか | 入力ファイル一覧 |
| 日次 | 不正行や欠損を黙って除外していないか | 解析件数と終了コード |
| 日次 | 想定する識別子がすべて存在するか | 稼働台帳との照合結果 |
| 日次 | 異常通知が届いたか | 通知結果と送信時刻 |
| 月次 | 全対象日が確定しているか | 日次成果物の一覧 |
| 月次 | p95の名称と計算方法が一致するか | 集計方式の説明 |
| 月次 | 再実行で件数が増えないか | 同一入力の比較結果 |
| 変更時 | 閾値の変更理由が追跡できるか | 判定規則の版と承認記録 |
| 定期 | 保存データから復元できるか | 復元確認の実施記録 |

導入時には、正常入力だけでなく、重複行、負数、p95の無限値、列不足、観測ゼロ、月内の欠日を用意する。不正入力で公開済み成果物が更新されないことまで確認する。

運用記録には実行開始・終了時刻、対象日、入力ハッシュ、プログラムの版、出力先を残す。出力先には必要な担当者だけがアクセスできる権限を設定し、原文ログの保存期間は集計済みデータと分けて定める。障害調査に必要な期間を確保しつつ、不要な個人情報を長期保管しない。

担当交代時には、一日分の再集計と一か月分の再作成を実施する。手順書だけで入力を特定し、欠損を検出し、訂正理由を記録できれば、日々の集計を個人の記憶から切り離せる。
