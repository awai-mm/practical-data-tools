# 第5章 再発防止につながる閾値設定とアラート疲労の回避

**本章の焦点**：ノイズを減らすフィルタリング規則

---

## 5.1 実務における課題の整理と設計方針

高価な監視SaaSを入れる前の小規模システムや業務バッチにおいて、エラー率急増・レイテンシ悪化・リトライ多発を数秒で要約・可視化する実務ハンドブック＆ツール。

現場の業務フローにおいて、「ノイズを減らすフィルタリング規則」を曖昧なまま手作業で処理していると、担当者ごとの判断ブレや集計ミスが避けられません。本章では、入力データの構造を厳密に定義し、再現性のある検算・判定プロセスへ落とし込む手順を解説します。

### 標準入力カラム定義（主キー：`endpoint_id`）

- `endpoint_id`
- `service_name`
- `total_requests`
- `error_5xx_count`
- `error_4xx_count`
- `p95_latency_ms`
- `timeout_count`

---

## 5.2 自動検証・計算機能（コアロジック）

本パッケージで提供するブラウザ版ワークベンチ（`log_error_digest_workbench.html`）およびコマンドラインツール（`log_error_digest_cli.py`）は、以下の機能を標準搭載しています。

1. **5xxエラー率算出および閾値判定**
2. **P95レイテンシ劣化検出**
3. **タイムアウト発生監視**
4. **日次健全性サマリCSV出力**

---

## 5.3 実践コマンドと運用チェックポイント

手元のCSVデータに対して一括検証と正規化を実行する場合は、以下のコマンドを使用します。

```bash
/usr/bin/python3 log_error_digest_cli.py samples/problem_data.csv \
  --key endpoint_id \
  --fix \
  --output-csv samples/verified_output.csv \
  --output-json samples/report.json
```

### 現場導入時の確認事項

| 確認フェーズ | 点検項目 | 合格基準 |
| :--- | :--- | :--- |
| **1. 入力データ受領時** | 必須カラム（全7列）の存在と主キー `endpoint_id` の一意性 | 欠損列0件・重複キー0件 |
| **2. 数値・日付正規化** | 全角数字・カンマ・通貨記号・前後空白の除去 | 型変換エラー0件 |
| **3. 業務ロジック検算** | ノイズを減らすフィルタリング規則に関する閾値および計算整合性 | 指摘エラー0件（終了コード `0`） |
| **4. 証跡保存** | 修正前後の差分確認とJSONレポートの保管 | 月次フォルダへの保存完了 |
