# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

見積計算を日々の運用に組み込むとき、最初に整えるべきものは計算速度ではない。入力の誤りを止め、承認した版を識別し、失敗した処理が前日の結果を最新に見せない仕組みである。本章では、Python標準ライブラリだけで構成する検証・集計・保存のレシピを示す。

運用対象は一つの案件、一つの通貨、一つの見積版を含むCSVとする。複数案件を同じファイルに入れるなら、案件識別子を追加し、案件単位に集計を分ける必要がある。必須カラムだけでは案件も通貨も区別できない。

## 7.1 入力契約を先に固定する

基本CSVは次の形式とする。時間は時間単位、倍率は無次元、単価は円毎時で入力する。桁区切りのカンマや通貨記号は数値セルへ入れない。

```csv
task_id,phase_name,task_name,base_hours,risk_multiplier,hourly_rate,hourly_cost
T-001,実装,画面改修,120,1.10,10000,6000
T-002,検証,結合テスト,40,1.10,10000,6000
T-003,管理,進行管理,20,1.00,10000,6000
```

このレシピでは、空欄、重複した識別子、負数、無限大、非数値を拒否する。倍率は1以上とし、効率改善による工数削減は`base_hours`の根拠を更新して表現する。ゼロ時間とゼロ単価は無条件に通さず、例外案件として入力前に処理する方針とした。

| 項目 | 運用上の意味 | 主な確認点 |
|---|---|---|
| task_id | 版をまたいで追跡する作業識別子 | 重複・使い回しがない |
| phase_name | 工程別集計の分類 | 表記が統一されている |
| task_name | 作業内容 | 完了条件と対応する |
| base_hours | 通常条件の工数 | 既知の付帯作業を含む |
| risk_multiplier | 残る不確実性 | 根拠と対象が明確 |
| hourly_rate | 顧客向け時間単価 | 契約額と混同しない |
| hourly_cost | 社内原価単価 | 適用期間が一致する |

直接費と目標粗利率は実行引数で与える。固定価格契約では、時間単価から求めた予定売上と契約売上が一致するとは限らないため、採算判定には承認済み契約売上を別途渡せるようにする。

## 7.2 日次レシピ：不正な入力を止めて採算を計算する

次のコードを`estimate_check.py`として保存する。金額の計算には`Decimal`を使い、必要売上だけを最後に円単位で切り上げる。各行で丸める契約では結果が変わるため、契約上の端数処理は別途合わせる。

```python
import argparse
import csv
import hashlib
import io
import json
import os
import sys
import tempfile
from datetime import datetime, timezone
from decimal import Decimal, InvalidOperation, ROUND_CEILING
from pathlib import Path

FIELDS = (
    "task_id", "phase_name", "task_name", "base_hours",
    "risk_multiplier", "hourly_rate", "hourly_cost",
)


def number(value, label, minimum, strict=False):
    try:
        result = Decimal(value)
    except (InvalidOperation, TypeError, ValueError):
        raise ValueError(f"{label}: 数値形式が不正です")
    if not result.is_finite():
        raise ValueError(f"{label}: 有限値が必要です")
    if result < minimum or (strict and result == minimum):
        raise ValueError(f"{label}: 下限条件を満たしません")
    return result


def calculate(raw, target, direct, contract):
    reader = csv.DictReader(
        io.StringIO(raw.decode("utf-8-sig"), newline=""),
        strict=True,
    )
    header = reader.fieldnames
    if (not header or len(header) != len(set(header))
            or not set(FIELDS).issubset(header)):
        raise ValueError("ヘッダーの欠落または重複があります")

    seen = set()
    hours = Decimal("0")
    sales = Decimal("0")
    cost = direct

    for line, row in enumerate(reader, 2):
        if None in row or any(v is None for v in row.values()):
            raise ValueError(f"{line}行: 列数が一致しません")
        if any(not row[k].strip() for k in FIELDS):
            raise ValueError(f"{line}行: 必須項目が空欄です")

        task = row["task_id"].strip()
        if task in seen:
            raise ValueError(f"{line}行: task_idが重複しています")
        seen.add(task)

        base = number(row["base_hours"], "工数", 0, True)
        risk = number(row["risk_multiplier"], "倍率", 1)
        rate = number(row["hourly_rate"], "売価単価", 0, True)
        unit = number(row["hourly_cost"], "原価単価", 0, True)
        adjusted = base * risk
        hours += adjusted
        sales += adjusted * rate
        cost += adjusted * unit

    if not seen:
        raise ValueError("作業行がありません")

    revenue = sales if contract is None else contract
    required = (cost / (1 - target)).quantize(
        Decimal("1"), rounding=ROUND_CEILING
    )
    margin = (revenue - cost) / revenue
    return {
        "task_count": len(seen),
        "adjusted_hours": str(hours),
        "calculated_sales": str(sales),
        "evaluated_sales": str(revenue),
        "sales_basis": "積算" if contract is None else "契約",
        "direct_cost": str(direct),
        "estimated_cost": str(cost),
        "target_margin": str(target),
        "gross_margin": str(margin),
        "required_sales": str(required),
        "meets_target": margin >= target,
    }


def atomic_json(path, payload):
    path.parent.mkdir(parents=True, exist_ok=True)
    temporary = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", dir=path.parent,
            prefix=path.name + ".", suffix=".tmp", delete=False,
        ) as stream:
            temporary = Path(stream.name)
            json.dump(payload, stream, ensure_ascii=False, indent=2)
            stream.write("\n")
            stream.flush()
            os.fsync(stream.fileno())
        os.replace(temporary, path)
    finally:
        if temporary is not None and temporary.exists():
            temporary.unlink()


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("source", type=Path)
    parser.add_argument("output", type=Path)
    parser.add_argument("--target", default="0.35")
    parser.add_argument("--direct-cost", default="0")
    parser.add_argument("--contract-sales")
    args = parser.parse_args()

    try:
        if args.source.resolve() == args.output.resolve():
            raise ValueError("入力と出力は別のパスにしてください")
        target = number(args.target, "目標粗利率", 0)
        if target >= 1:
            raise ValueError("目標粗利率は1未満にしてください")
        direct = number(args.direct_cost, "直接費", 0)
        contract = None
        if args.contract_sales is not None:
            contract = number(args.contract_sales, "契約売上", 0, True)

        raw = args.source.read_bytes()
        result = calculate(raw, target, direct, contract)
        result["input_sha256"] = hashlib.sha256(raw).hexdigest()
        result["processed_at"] = datetime.now(timezone.utc).isoformat()
        result["calculation_version"] = "1.0"
        atomic_json(args.output, result)
    except (ValueError, OSError, UnicodeError, csv.Error) as error:
        print(f"処理中止: {error}", file=sys.stderr)
        return 1
    return 0 if result["meets_target"] else 2


if __name__ == "__main__":
    sys.exit(main())
```

終了コード0は目標達成、1は入力または処理の異常、2は正常に計算できたが目標未達という意味である。目標未達でも結果ファイルを残すので、原因調査に使える。一方、入力不正では新しい結果を保存しない。

入力例の調整後工数は196時間、作業原価は1,176,000円である。直接費12万円、契約売上200万円を指定すると、総原価は1,296,000円、粗利率は35.2％、必要売上は1,993,847円となる。この既知の組合せを、導入時の照合用に使う。

入力は一度だけバイト列として読み、同じ内容を計算とハッシュ値の作成に使う。途中で元ファイルが差し替わっても、計算対象と識別値が食い違わない。ただし、ハッシュ値だけでは改ざんを防げない。保存先の更新権限と承認記録も必要になる。

## 7.3 バッチ連携：実行単位で結果とログを閉じ込める

日次の起動はOSのスケジューラに任せ、Python側で実行フォルダを分離する。次の例は入力の写しを保存し、その写しを検証する。実行日時だけでは衝突する可能性があるため、識別子も付ける。

```python
import subprocess
import sys
import uuid
from datetime import datetime, timezone
from pathlib import Path

root = Path(__file__).resolve().parent
stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
run = root / "runs" / f"{stamp}-{uuid.uuid4().hex[:12]}"
run.mkdir(parents=True, exist_ok=False)

snapshot = run / "input.csv"
snapshot.write_bytes((root / "incoming" / "estimate.csv").read_bytes())

command = [
    sys.executable, str(root / "estimate_check.py"),
    str(snapshot), str(run / "result.json"),
    "--target", "0.35",
    "--direct-cost", "120000",
    "--contract-sales", "2000000",
]
with (run / "process.log").open("w", encoding="utf-8") as log:
    completed = subprocess.run(
        command, stdout=log, stderr=subprocess.STDOUT,
        timeout=300, check=False,
    )

(run / "exit_code.txt").write_text(
    str(completed.returncode), encoding="utf-8"
)
sys.exit(completed.returncode)
```

入力元が書込み途中のファイルを公開すると、写しにも途中状態が入る。上流処理は一時ファイルへ書き終えてから名前を切り替え、公開後のファイルを直接編集しない運用にする。

タイムアウトや起動前の障害では、終了コードファイルが存在しない場合がある。その実行は未完了として扱う。スケジューラでは異常終了だけでなく、予定時刻を過ぎても実行記録がない状態を検知する。成功した日の結果を見せ続けるだけでは、停止を発見できない。

同じ結果ファイルへの書込みを避けても、二重実行による二重通知は残る。通知側は案件、見積版、入力ハッシュ値、計算条件の組合せで重複を判定する。目標未達は担当者レビューへ、処理異常は運用担当へ振り分ける。

## 7.4 月次レシピ：見積、実績、残作業を混ぜずに締める

必須カラムは見積用であり、実績時間や確定売上を保持する台帳ではない。月次では実績台帳を`task_id`で対応付ける。実績原価にリスク倍率を掛けてはいけない。

```text
完了時原価見込
  = 締め日までの実績原価
  ＋残作業の見込原価
  ＋未計上の直接費見込
```

残作業は「当初工数－実績時間」だけで決めない。使った時間が多くても、未完了の成果物が多ければ残作業は増える。担当者に完了条件と未処理項目を確認し、残りの基準工数と不確実性を更新する。

月末には、採用した実行フォルダ、実績台帳、原価単価の適用期間、契約売上、変更承認票を一つの締め版として固定する。日次の見積結果を合計すると同じ案件を何度も計上するため、案件ごとに締め日時点の採用版を一つ選ぶ。

翌月の修正は締め版を上書きせず、訂正版として差分理由と承認者を残す。工数差、単価差、範囲変更、直接費差を分けると、見積精度の問題と営業判断による利益減少を区別できる。

## 7.5 実務監査チェックリスト

日次では、入力検証と処理の完了を確認する。

- [ ] 必須カラム、識別子の一意性、数値の範囲を検査した。
- [ ] 対象案件、通貨、見積版が入力にひも付いている。
- [ ] 入力の写し、計算条件、結果、終了状態が保存されている。
- [ ] 未実行、処理異常、目標未達を区別して検知できる。
- [ ] 前回結果を今回の成功として扱っていない。

月次では、数字の意味と承認経路を確認する。

- [ ] 実装以外の検証、修正、管理、受入支援が含まれている。
- [ ] リスク倍率に根拠があり、同じリスクを重複計上していない。
- [ ] 原価単価、直接費、配賦費に二重計上がない。
- [ ] 未承認の変更売上を確定売上へ含めていない。
- [ ] 実績原価と残作業見込の対象期間が重複していない。
- [ ] 締め版から同じ計算結果を再現できる。
- [ ] 訂正理由、承認者、訂正前後の差分が追跡できる。

導入時には正常例に加え、重複識別子、倍率の空欄、売上ゼロ、目標粗利率1、出力先への書込み失敗を試す。計算が合うことと、誤った入力を止められることの両方を確認してから、日次運用へ移行する。
