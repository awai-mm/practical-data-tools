# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

運用を安定させるには、計算処理を一度動かすことより、入力の欠落を検知し、途中失敗から安全に再開できることが重要である。本章では、Python標準ライブラリによる入力検証と発注計算を示し、日次・月次バッチにつなぐ。コードは整数個の商品を対象とし、仕入条件として`moq`が最低数量と発注倍数を兼ねる場合に限定する。

## 7.1 入力契約を先に決める

必須8カラムは名称だけでなく、意味と単位を固定する。需要統計とリードタイムは暦日でそろえ、現在庫は利用可能な良品在庫とする。未出庫引当は現在庫からまだ差し引かれていない数量として扱う。すでに引当控除済みの在庫を使う場合は、再度控除してはいけない。

| カラム | このレシピでの検証条件 |
|---|---|
| sku_code | 空欄不可、文字列保持、重複不可 |
| item_name | 空欄不可 |
| current_stock | 0以上の整数 |
| avg_daily_demand | 0以上の有限数 |
| demand_stddev | 0以上の有限数 |
| lead_time_days | 1以上の整数 |
| unit_cost | 0以上の有限数 |
| moq | 1以上の整数 |

商品コードの先頭ゼロは識別子の一部である。数値化せず、前後の空白を除去した結果も重複検査する。負在庫や当日調達は、黙ってゼロや1日に置き換えず、別の業務ルールで扱う。

日次バッチには、この8カラムに加えて、同じ基準時刻の発注残・引当情報が必要である。補助データに行がない場合をゼロとみなすと、連携漏れと残数ゼロを区別できない。残数がない商品も明示的にゼロの行を渡す契約にする。

## 7.2 レシピ1：入力検証と推奨発注数の計算

次の例は、欠損、重複、非数、無限大、桁不足の行を検知して処理を止める。エラーのある商品だけを除外して正常終了させる方式は、発注漏れを見逃しやすいため採用しない。

```python
import csv
from decimal import Decimal, ROUND_CEILING

FIELDS = (
    "sku_code", "item_name", "current_stock",
    "avg_daily_demand", "demand_stddev",
    "lead_time_days", "unit_cost", "moq",
)
WHOLE = {"current_stock", "lead_time_days", "moq"}

def number(value, name):
    x = Decimal(value)
    if not x.is_finite() or x < 0:
        raise ValueError(f"{name}: 有限の非負数が必要")
    if name in WHOLE and x != x.to_integral_value():
        raise ValueError(f"{name}: 整数が必要")
    if name in {"lead_time_days", "moq"} and x < 1:
        raise ValueError(f"{name}: 1以上が必要")
    return x

def read_items(path):
    items = []
    seen = set()
    with open(path, encoding="utf-8-sig", newline="") as f:
        reader = csv.DictReader(f)
        headers = reader.fieldnames or []
        if len(headers) != len(set(headers)):
            raise ValueError("ヘッダー重複")
        if not set(FIELDS).issubset(headers):
            raise ValueError("必須カラム不足")

        for line, raw in enumerate(reader, 2):
            try:
                if None in raw or any(v is None for v in raw.values()):
                    raise ValueError("列数不一致")
                row = {k: raw[k].strip() for k in FIELDS}
                if any(not v for v in row.values()):
                    raise ValueError("必須値が空欄")
                sku = row["sku_code"]
                if sku in seen:
                    raise ValueError("商品コード重複")
                for key in FIELDS[2:]:
                    row[key] = number(row[key], key)
                seen.add(sku)
                items.append(row)
            except Exception as exc:
                raise ValueError(f"{line}行目: {exc}") from exc
    if not items:
        raise ValueError("入力が空")
    return items

def up(x):
    return int(x.to_integral_value(rounding=ROUND_CEILING))

def recommend(row, on_order, allocated, review_days=7):
    if type(review_days) is not int or review_days < 1:
        raise ValueError("見直し間隔は正の整数")
    on_order = number(str(on_order), "current_stock")
    allocated = number(str(allocated), "current_stock")

    mean = row["avg_daily_demand"]
    sd = row["demand_stddev"]
    lead = row["lead_time_days"]
    z = Decimal("1.65")
    span = lead + Decimal(review_days)

    safety = up(z * sd * lead.sqrt())
    point = up(mean * lead + Decimal(safety))
    target = up(mean * span + z * sd * span.sqrt())
    position = row["current_stock"] + on_order - allocated
    gap = max(Decimal(0), Decimal(target) - position)
    moq = int(row["moq"])
    qty = up(gap / Decimal(moq)) * moq if position <= point else 0

    return {
        "sku_code": row["sku_code"],
        "safety_stock": safety,
        "reorder_point": point,
        "target_stock": target,
        "inventory_position": int(position),
        "recommended_qty": qty,
        "estimated_cost": str(Decimal(qty) * row["unit_cost"]),
    }
```

この関数は計算結果を返すだけで、仕入先への注文は登録しない。入力値の規模に応じた上限検査、廃番・販促・季節商品の例外判定、発注金額の承認は呼び出し側に置く。小数数量を扱う商品では、整数検証と丸め単位を商品別に変更する必要がある。

平均需要がゼロでも変動が残る商品は、通常補充の対象にする前に履歴を確認する。また、この例は固定リードタイムの近似であり、納期変動を含む第6章の計算をそのまま実装したものではない。

## 7.3 レシピ2：完成した結果だけを公開する

出力先へ直接書き込むと、処理途中のCSVを後続バッチが読み込む可能性がある。同じディレクトリに一時ファイルを書き、完了後に置き換える。

```python
import os
import tempfile
from pathlib import Path

def publish_csv(path, rows):
    if not rows:
        raise ValueError("出力が空")
    path = Path(path)
    temp_name = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", newline="",
            dir=path.parent, delete=False
        ) as f:
            temp_name = f.name
            writer = csv.DictWriter(f, fieldnames=list(rows[0]))
            writer.writeheader()
            writer.writerows(rows)
            f.flush()
            os.fsync(f.fileno())
        os.replace(temp_name, path)
    finally:
        if temp_name and os.path.exists(temp_name):
            os.unlink(temp_name)
```

この方式は、対象ファイルシステムが置換の原子性を提供することを前提とする。複数ファイルをまとめて更新する保証や、停電時の完全な永続性まで提供するものではない。

実運用では実行ごとの専用ディレクトリを使い、結果CSVと実行記録を保存した後、最後に完了通知ファイルを公開する。後続処理はその通知を起点にする。失敗時に前日の出力が残っていても、当日成功と誤認しない設計になる。出力ディレクトリの作成権限や保存先の存在は、実行前に確認しておく。

## 7.4 日次バッチ連携の実装レシピ

日次処理は「取得、検証、計算、承認、登録、照合」の順に接続する。単に時刻をずらして起動するだけでは、前工程の遅延を吸収できない。各工程の完了状態と基準時刻を引き渡す。

1. 在庫・発注残・引当を同一締め時刻で取得する。
2. 入力ファイルの件数、対象日、商品コード集合を照合する。
3. 有効な需要統計版と仕入条件版を選び、推奨値を計算する。
4. 高額発注、急増、廃番、欠品中の商品を確認対象に分ける。
5. 承認済みの発注案を登録し、受付番号を保存する。
6. 登録結果と発注残を照合し、日次処理を完了する。

発注残は未入荷数量を使い、取消済み・入荷済み数量を含めない。納期未定や大幅遅延の発注は、単純に全量加算すると不足を隠すため、日付別の入出庫見込みでも検査する。

二重発注防止の識別子は、承認した発注案の版、商品、仕入先などから決定する。同じ発注案を再送する場合は同じ識別子を使う。送信時に新しい時刻や乱数を付けるだけでは、再送が別注文として扱われる。

通信切断で結果が不明になった場合は、先に受付状態を照会する。受付済みなら結果を回収し、未受付が確認できた場合だけ再送する。外部側に照会手段がなければ、不明案件を保留して照合する。ローカルの完了印だけでは、送信直後の停止に対応できない。

## 7.5 月次バッチと検証用の再計算

月次処理では需要統計、納期統計、ABC分類、滞留判定条件を更新する。平均と標準偏差は同じ日次系列から算出し、通常営業日の需要ゼロと欠品による観測不足を区別する。期間中の標本から推定するなら、標準ライブラリの`statistics.stdev`を使えるが、観測が2件未満の商品は別途処理する。

ABC分類には返品・値引き後の売上を使い、集計期間と通貨を統一する。売上合計がゼロ以下の場合は構成比を計算せず、判定保留にする。売上が負の商品、同額商品、構成比の境界にある商品の扱いも固定する。必須8カラムだけから売上貢献度を作らない。

新設定は直ちに本番適用せず、旧設定と同じ履歴に対して比較する。欠品日数、平均在庫、発注回数、発注金額を確認し、改善が特定商品だけに偏っていないかを見る。履歴検証では、その当日に利用できた情報だけを使う。後日判明した納期や需要を先に与えると、実運用より良い結果になる。

実行記録には、入力のハッシュ、設定版、プログラム版、基準時刻、対象件数、出力ハッシュを残す。`hashlib.sha256`によるハッシュは同一内容の確認に役立つが、それだけで改ざんを防ぐものではない。保存先の権限管理も必要である。

## 7.6 実務監査チェックリスト

監査は、担当者の記憶ではなく、入力・計算・登録の証跡をたどって行う。

| 確認事項 | 合格条件・確認する証跡 |
|---|---|
| 入力の完全性 | 必須列、件数、重複、商品集合の検証記録がある |
| 時点の整合 | 在庫・発注残・引当の基準時刻が一致する |
| 需要統計 | 対象期間、欠品日の扱い、観測件数が分かる |
| 調達条件 | 日数単位、検収期間、分納の扱いが明確である |
| 発注数量 | 最低数量と発注倍数を区別して確認している |
| ABC分類 | 売上明細まで集計根拠を追跡できる |
| 滞留判定 | 最終出庫日とロット別残数の根拠がある |
| 再実行 | 同一発注案を二重登録しない証拠がある |
| 例外承認 | 変更理由、変更前後、担当者、日時が残る |
| 障害復旧 | 最終成功地点と再開地点を特定できる |

境界値の確認も欠かせない。在庫ポジションが発注点と等しい場合、不足が発注単位のちょうど倍数の場合、引当超過で在庫ポジションが負の場合を検査する。第6章のフィルター例なら、安全在庫18個、発注点102個、目標在庫193個、推奨発注数140個が得られることを確認する。

障害時は、入力不備なら修正後に再計算し、出力中断なら完成していないファイルを公開しない。外部登録後の障害では、受付状態の照合を優先する。旧設定への切戻しも、すでに登録した注文を取り消す操作とは分ける。

日次の完了条件は処理の正常終了だけではない。対象件数が一致し、当日の結果が公開され、承認・登録・照合まで必要な工程が終わっていることを確認して、運用担当者へ引き継ぐ。
