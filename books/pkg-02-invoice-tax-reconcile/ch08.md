# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

日次処理では、入力の誤りを早く見つける。月次処理では、対象期間全体の欠落、重複、訂正履歴を確認する。この二つを同じ検算ロジックで支えると、担当者や実行日による判定の揺れを減らせる。

本章のコードは、円建ての通常請求書を対象とする。金額は非負の整数とし、返品、取消し、外貨、複数通貨、税率区分が未確定のデータは別の確認経路へ回す。標準ライブラリだけで構成するが、導入時には実際の入力形式と運用環境で確認する。

## 7.1 入力データと検算ルールを分離する

CSVには、指定された10カラムを必須とする。一方、端数処理や確定済みの源泉徴収額は、別の検算ルールとして渡す。請求書の値をそのまま正解値にコピーすると、誤りを見逃すためである。

ルールの例は次のとおりである。金額はCSVと同様に文字列で持たせる。

```python
rules = {
    "INV-101": {
        "rounding": "floor",
        "withholding_tax": "0",
    },
    "INV-201": {
        "rounding": "floor",
        "withholding_tax": "153150",
    },
}
```

`rounding`には`floor`、`half_up`、`ceil`を指定する。新しい取引先や請求書について、ルールが見つからない場合は確認対象にする。既定値で切捨てを適用すると、設定漏れが正常処理に見えてしまう。

この例の源泉徴収額は、対象判定と支払単位の計算を別工程で確認した値である。実運用では、ルール版、適用開始日、根拠資料、確認者も保存する。

## 7.2 税額・源泉徴収額・請求額を独立して検査する

金額の読み込みでは、空欄、桁区切り、少数、負数を黙って変換しない。受け付ける形式を限定し、形式違反を行番号付きで返す。桁区切りを許す必要がある場合は、入力正規化を別工程に分け、その前後の値を追跡できるようにする。

以下は、CSVを読み、各行の問題と単純な着金差額を返す関数である。

```python
import csv
import re
from datetime import date
from decimal import Decimal, ROUND_DOWN, ROUND_HALF_UP, ROUND_UP

required = (
    "invoice_id", "issue_date", "vendor_name",
    "subtotal_10", "tax_10", "subtotal_8", "tax_8",
    "withholding_tax", "billed_total", "paid_amount",
)
roundings = {
    "floor": ROUND_DOWN,
    "half_up": ROUND_HALF_UP,
    "ceil": ROUND_UP,
}

def yen(value):
    if not isinstance(value, str):
        raise ValueError("金額の型が不正")
    if re.fuテキスト処理系atch(r"0|[1-9][0-9]*", value) is None:
        raise ValueError("金額の書式が不正")
    if len(value) > 15:
        raise ValueError("金額が運用上限を超過")
    return int(value)

def tax(base, rate, rounding):
    value = Decimal(base) * Decimal(rate)
    return int(value.quantize(Decimal("1"), rounding=rounding))

def inspect_csv(path, rules):
    reports, seen = [], set()
    with open(path, encoding="utf-8-sig", newline="") as stream:
        reader = csv.DictReader(stream)
        header = reader.fieldnames or []
        if len(header) != len(set(header)):
            raise ValueError("ヘッダーが重複")
        if not set(required).issubset(header):
            raise ValueError("必須カラムが不足")
        for number, row in enumerate(reader, start=2):
            ident = row.get("invoice_id")
            try:
                if None in row or any(v is None for v in row.values()):
                    raise ValueError("列数が不一致")
                if not ident or ident != ident.strip():
                    raise ValueError("請求識別子が不正")
                if ident in seen:
                    raise ValueError("請求識別子が重複")
                seen.add(ident)
                issued = date.fromisoformat(row["issue_date"])
                if issued.isoformat() != row["issue_date"]:
                    raise ValueError("日付の書式が不正")
                if not row["vendor_name"].strip():
                    raise ValueError("供給者名が空欄")
                amounts = {key: yen(row[key]) for key in required[3:]}
                rule = rules[ident]
                rounding = roundings[rule["rounding"]]
                expected = {
                    "tax_10": tax(amounts["subtotal_10"], "0.10", rounding),
                    "tax_8": tax(amounts["subtotal_8"], "0.08", rounding),
                    "withholding_tax": yen(rule["withholding_tax"]),
                }
                expected["billed_total"] = (
                    amounts["subtotal_10"] + amounts["subtotal_8"]
                    + expected["tax_10"] + expected["tax_8"]
                    - expected["withholding_tax"]
                )
                if expected["billed_total"] < 0:
                    raise ValueError("通常請求の対象外")
                errors = [
                    key for key, value in expected.items()
                    if amounts[key] != value
                ]
                reports.append({
                    "line": number, "invoice_id": ident,
                    "errors": errors,
                    "gap": amounts["billed_total"] - amounts["paid_amount"],
                })
            except (ValueError, KeyError) as error:
                reports.append({
                    "line": number, "invoice_id": ident,
                    "errors": [str(error)], "gap": None,
                })
    return reports
```

`Decimal`へ渡す税率は文字列にする。いったん小数を浮動小数点数として作ってから変換すると、その時点の表現誤差を引き継ぐ可能性がある。

このコードでは金額を非負に限定しているため、`ROUND_DOWN`を切捨て、`ROUND_UP`を切上げとして使える。負の訂正額を受け付ける設計へ拡張する場合は、ゼロ方向と負の無限大方向の違いを含め、端数処理を再定義する必要がある。

`errors`が空でも、`gap`だけで消込完了とはしない。正の差額は不足または控除の確認対象、負の差額は過入金または誤配賦の確認対象である。手数料などの承認済み控除は、別台帳と突き合わせて判定する。

## 7.3 源泉徴収の段階計算を部品化する

次の関数は、対象額と適用条件が確定した後に使う計算部品である。100万円以下の部分に10.21%、超過部分に20.42%を適用し、合計した後の1円未満を切り捨てる。

```python
def withholding(base):
    if type(base) is not int or base < 0 or base > 10**15 - 1:
        raise ValueError("計算対象額が不正")
    lower = min(base, 1_000_000)
    upper = max(base - 1_000_000, 0)
    value = (
        Decimal(lower) * Decimal("0.1021")
        + Decimal(upper) * Decimal("0.2042")
    )
    return int(value.quantize(Decimal("1"), rounding=ROUND_DOWN))
```

この関数は、源泉徴収の要否を判断しない。また、請求書の税抜合計を無条件に渡す用途ではない。報酬の種類、消費税の扱い、対象外項目、支払単位を上流工程で確定する。

複数請求書をまとめて支払う場合、適用する計算単位を確認してから対象額を集計する。計算結果を請求書へ分ける場合は、配賦後の合計一致も検査する。請求書ごとの再計算結果が支払単位の結果と一致するとは限らない。

## 7.4 日次バッチの連携レシピ

日次処理は、受領、検算、確認待ちへの振分け、確定結果の公開、という順序にする。

1. 連携元は一時名でCSVを書き、書込み完了後に正式名へ変更する。
2. 受領側は正式名のファイルだけを処理対象にする。
3. 入力ファイルとルールの識別情報を記録し、検算を実行する。
4. 形式不正や計算不一致を含むデータは、確定処理へ渡さない。
5. 着金差額は配賦台帳、手数料、相殺の承認記録と照合する。
6. 確定結果と実行記録を保存し、処理済み状態を更新する。

同じファイルを再受領したときは、ファイル名だけで判断しない。`hashlib.sha256`で求めた内容のハッシュ値、対象期間、連携元を組み合わせて識別する。ルールを変更して再検算する場合は、新しい実行として保存し、前回結果との対応を残す。

実行中に停止しても、途中まで書かれた結果を後続処理が読まないようにする。次はJSON形式の検算報告を一時ファイルに書き、完成後に置き換える例である。

```python
import json
import os
import tempfile
from pathlib import Path

def publish_report(destination, reports):
    destination = Path(destination)
    staged = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", delete=False,
            dir=destination.parent,
        ) as stream:
            staged = Path(stream.name)
            json.dump(reports, stream, ensure_ascii=False)
            stream.flush()
            os.fsync(stream.fileno())
        os.replace(staged, destination)
    finally:
        if staged is not None:
            staged.unlink(missing_ok=True)
```

出力先の親ディレクトリは事前に用意する。同じディレクトリに一時ファイルを作ることで、同一ファイルシステム内の置換を利用できる。実行ごとの報告は固有のパスに保存し、過去の報告を上書きしない。

この方法で保護できるのは単一ファイルの公開である。会計登録、配賦台帳更新、処理済み記録をまとめて確定する場合は、保存先のトランザクションや一意制約も使う。同時実行を防ぐ仕組みは、ジョブ管理側にも設ける。

終了コードは、例えば正常を0、確認待ちを2、処理障害を3とする。確認待ちは担当者へ回し、処理障害は原因を解消して再実行する。再実行で同じ銀行取引や配賦が増えないことを、運用開始前に確認する。

## 7.5 月次処理では「残高」と「期間」を検査する

日次検算がすべて正常でも、月次で欠落がないとは限らない。未受領ファイルや、締め後に届いた訂正データは、行単位の検算だけでは見つからない。

月次処理では、連携元の対象件数、請求額合計、着金額合計と照合する。前月末の未消込残に、当月の請求、着金、承認済み控除、訂正を反映し、当月末の未消込残へつながることも確認する。

`paid_amount`は累計値である。日次ファイルに同じ請求書の累計額が繰り返し載る場合、それらを月次で合算してはいけない。基準日時点の最新状態を選ぶか、別の入金明細から再集計する。

締め後の訂正では、元の月次結果を保存したうえで、訂正版の基準日と対象版を明示する。請求書発行日で請求対象を選び、銀行着金日で入金対象を選ぶなど、集計目的ごとの日付条件を固定する。

## 7.6 導入時の受入確認と実務監査チェックリスト

受入確認には、正常データだけでなく、第6章の失敗を含める。期待結果は、検算プログラムとは独立した計算で用意する。

| 確認データ | 期待する判定 |
|---|---|
| 税額597円・300円の混在請求 | 両方の税額不一致を検出 |
| 報酬1,250,000円の段階計算 | 源泉徴収額153,150円 |
| 着金163,670円を2件へ全額登録 | 配賦合計超過を検出 |
| 金額空欄、負数、桁区切り付き | 入力形式違反 |
| 同じ請求識別子が複数行 | 重複として確定処理を停止 |
| 未登録の端数処理ルール | 設定不足として確認待ち |

二重配賦の検出は、請求書CSVの検査とは別に、銀行取引を単位として行う。片方の検査を通過したことを理由に、もう片方を省略しない。

### 日次の確認

- [ ] 必須カラムがあり、ヘッダーと請求識別子に重複がない。
- [ ] 空欄、ゼロ、不正な金額を区別している。
- [ ] 税率区分と端数処理ルールが確定している。
- [ ] 税額、源泉徴収額、支払請求額を独立して検算している。
- [ ] 銀行取引ごとの配賦合計が着金額を超えていない。
- [ ] 差額を手数料と判断した根拠と承認記録がある。
- [ ] 確認待ちの案件に担当者と対応期限が設定されている。

### 月次の確認

- [ ] 連携元の件数と金額合計に一致している。
- [ ] 累計着金額を日次ファイル間で重複加算していない。
- [ ] 締め日前後の着金と訂正を正しい期間へ反映している。
- [ ] 源泉徴収の支払単位と請求書への配賦が整合している。
- [ ] 前月残高から当月残高への増減を説明できる。
- [ ] 原本、訂正版、検算ルール版、確認者を追跡できる。
- [ ] 障害後の再実行で請求、着金、配賦が増殖しない。
- [ ] 復旧手順で前回の確定結果を再現できる。
