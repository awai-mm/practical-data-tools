# 第1章 請求書と入金明細の1円ズレが起きる構造的原因

**本章の焦点**：税率別合算後の端数計算ルールと明細行単位端数の違い

---

## 1.1 実務における課題の整理と設計方針

軽減税率8%と標準税率10%の混在、端数処理（切捨・四捨五入・切上）、源泉徴収税額（10.21% / 20.42%）、振込手数料差し引き後の入金消込ズレを一括検証する実務ハンドブック＆計算機パック。

現場の業務フローにおいて、「税率別合算後の端数計算ルールと明細行単位端数の違い」を曖昧なまま手作業で処理していると、担当者ごとの判断ブレや集計ミスが避けられません。本章では、入力データの構造を厳密に定義し、再現性のある検算・判定プロセスへ落とし込む手順を解説します。

### 標準入力カラム定義（主キー：`invoice_id`）

- `invoice_id`
- `issue_date`
- `vendor_name`
- `subtotal_10`
- `tax_10`
- `subtotal_8`
- `tax_8`
- `withholding_tax`
- `billed_total`
- `paid_amount`

---

## 1.2 自動検証・計算機能（コアロジック）

本パッケージで提供するブラウザ版ワークベンチ（`invoice_reconcile_workbench.html`）およびコマンドラインツール（`invoice_reconcile_cli.py`）は、以下の機能を標準搭載しています。

1. **税率別端数検算**
2. **源泉徴収税額検算**
3. **入金差額・振込手数料判定**
4. **検算済みCSV出力**

---

## 1.3 実践コマンドと運用チェックポイント

手元のCSVデータに対して一括検証と正規化を実行する場合は、以下のコマンドを使用します。

```bash
/usr/bin/python3 invoice_reconcile_cli.py samples/problem_data.csv \
  --key invoice_id \
  --fix \
  --output-csv samples/verified_output.csv \
  --output-json samples/report.json
```

### 現場導入時の確認事項

| 確認フェーズ | 点検項目 | 合格基準 |
| :--- | :--- | :--- |
| **1. 入力データ受領時** | 必須カラム（全10列）の存在と主キー `invoice_id` の一意性 | 欠損列0件・重複キー0件 |
| **2. 数値・日付正規化** | 全角数字・カンマ・通貨記号・前後空白の除去 | 型変換エラー0件 |
| **3. 業務ロジック検算** | 税率別合算後の端数計算ルールと明細行単位端数の違いに関する閾値および計算整合性 | 指摘エラー0件（終了コード `0`） |
| **4. 証跡保存** | 修正前後の差分確認とJSONレポートの保管 | 月次フォルダへの保存完了 |
