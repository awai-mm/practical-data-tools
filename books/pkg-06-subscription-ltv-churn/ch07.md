# 第6章 現場で実際に起きたトラブル事例と完全復旧ケーススタディ

本章では、継続課金事業で起こりやすい失敗を、発見から再計算、意思決定の修正まで追う。各事例は実務上の論点を検証するための仮想ケースであり、特定企業の実績を示すものではない。「完全復旧」は、計算結果の修正だけでなく、影響範囲の特定、誤った判断の撤回、再発防止策の運用開始までを指す。

計算条件を統一する。月初の契約者が当月の売上と粗利を生み、解約は月末に発生する。新規獲得、再契約、値上げ、割引率は、明記しない限り含めない。割合カラムは「2％なら2」と記録し、計算時に100で割る。

| 必須カラム | 意味 | 入力例 |
|---|---|---:|
| plan_id | プランの安定した識別子 | basic |
| plan_name | 表示用のプラン名 | ベーシック |
| active_users | 基準日時点の有効契約者数 | 1,000 |
| arpu_jpy | 1契約者当たり月次売上 | 10,000 |
| gross_margin_pct | 売上に対する粗利率 | 80 |
| monthly_churn_pct | 月次契約者解約率 | 2 |
| cac_jpy | 新規有料契約者1人当たり獲得費 | 120,000 |

「契約者数」と「請求件数」は同じとは限らない。集計単位と基準日時を付帯情報に残し、計算式より先に分母を確定させる。

## 6.1 事例1：割合の単位違いで許容CACが100倍になった

### 発生した失敗と数値への影響

担当者は、表計算上の「2％」をCSVへ出力した。出力値は内部表現の`0.02`だったが、受け側は「2％なら2」を要求していた。この結果、解約率は2％から0.02％へ縮小して扱われた。

対象プランは契約者1,000人、ARPU10,000円、粗利率80％、CAC120,000円だった。1人当たり月次粗利を \(g\)、月次解約率を \(c\) とすると、一定解約率を仮定した粗利LTVは次式となる。

\[
LTV=\frac{g}{c},\qquad g=ARPU\times粗利率
\]

| 指標 | 正しい入力：2％ | 誤った入力：0.02％ |
|---|---:|---:|
| 月次解約率の計算値 | 0.02 | 0.0002 |
| 1人当たり月次粗利 | 8,000円 | 8,000円 |
| 粗利LTV | 400,000円 | 40,000,000円 |
| LTVがCACの3倍以上となるCAC上限 | 約133,333円 | 約13,333,333円 |
| 12回の月末解約後のMRR | 約7,847,167円 | 約9,976,026円 |

MRRは初期MRRに \((1-c)^{12}\) を掛けた値である。初月の売上を第1月と呼ぶ場合、第12月の売上に掛ける指数は11になる。月番号と経過した解約回数を混同しないことも重要だ。

誤った集計を見た責任者は、獲得費に大きな余裕があると判断した。しかし、粗利LTVの大きさと回収の速さは別問題である。解約を無視した回収期間は120,000÷8,000＝15ヶ月だが、解約を含む累積期待粗利は次式となる。

\[
G_n=g\frac{1-(1-c)^n}{c}
\]

正しい2％では、17ヶ月の累積期待粗利は約116,271円、18ヶ月では約121,946円となり、回収は18ヶ月目にずれる。

### 原因分析と完全復旧

直接原因は割合の表現違いだった。背景には、CSVの列名だけを共有し、単位と算定条件を契約として定義していなかったことがある。`0.02`は形式上有効な数値なので、数値型の検査だけでは発見できない。

復旧では、まず該当ファイルの公開を止め、直前の正常な集計へ表示を戻した。続いて、元の課金明細から月初契約者数と解約者数を再集計し、1,000人中20人の解約で2％だったことを確認した。修正CSVによる再計算後、影響を受けた予算案、獲得単価の上限表、回収期間の一覧を差し替えた。

予算承認後に発生した支出は、再計算で取り消せるものではない。既支出額と未執行額を分け、未執行の増額分を停止したうえで、既支出分の獲得コホートを追跡対象に加えた。

### 再発防止手順

1. カラム仕様に「割合は百分率で保存」と記載し、正常例と誤り例を添える。
2. 月初契約者数と解約者数から求めた実測率を入力値と照合する。
3. 前月比が極端に変わった場合は公開を保留し、理由を記録する。
4. 12ヶ月MRRと回収月数を、既知の小さな検算データで確認する。

小さい解約率を一律に誤りと扱ってはいけない。季節要因や契約条件によっては実際に小さくなるため、異常検知は確認の入口として使う。

## 6.2 事例2：平均解約率でプラン別の赤字を隠した

### 発生した失敗と数値への影響

二つのプランを運営する事業で、経営資料には全体ARPUと全体解約率だけが掲載されていた。広告費は両プランとも、新規有料契約者1人当たり60,000円だった。

| 項目 | ベーシック | プロ |
|---|---:|---:|
| 月初契約者数 | 900人 | 100人 |
| ARPU | 3,000円 | 30,000円 |
| 粗利率 | 70％ | 70％ |
| 当月解約者数 | 90人 | 2人 |
| 月次契約者解約率 | 10％ | 2％ |
| 初期MRR | 2,700,000円 | 3,000,000円 |
| 粗利LTV | 21,000円 | 1,050,000円 |

全体ARPUは5,700円、契約者解約率は92÷1,000＝9.2％となる。この二つを単純に組み合わせると、粗利LTVは次のようになる。

\[
5,700\times0.7\div0.092\approx43,370円
\]

この値だけでは、どちらのプランへ獲得費を振り向けるべきか分からない。ベーシックはCAC60,000円が粗利LTV21,000円を上回り、仮定した条件のままでは回収できない。一方、プロは初月粗利21,000円、3ヶ月累積期待粗利約61,748円となり、3ヶ月目に回収する。

解約者の売上構成も異なる。当月に失われたMRRは330,000円で、売上ベースの解約率は約5.79％となる。契約者解約率9.2％を、そのまま全体MRRへ掛けると、失われる売上を過大に見積もる。

### 原因分析と完全復旧

原因は、契約者数による平均と売上による平均を、同じ指標として扱ったことだった。さらに、長く残るプロの構成比は時間とともに上がるため、初月の平均解約率を将来の全月へ適用すること自体に無理がある。

復旧時はプラン別に残存契約者数を計算し、その売上を合計した。

\[
MRR_t=\sum_p N_{p,0}\times ARPU_p\times(1-c_p)^t
\]

同じ初期契約者構成で1人当たりの期待粗利を求めるなら、プラン別LTVを人数で加重する。上の例では、0.9×21,000＋0.1×1,050,000＝123,900円となる。ただし、これは既存契約者構成についてのモデル値であり、将来の新規獲得にも同じ構成を使えるとは限らない。

復旧後の資料では、ベーシックの獲得拡大を止め、価格、提供原価、継続率を個別に見直した。プロについても、獲得数を増やしたときにCACが維持されるかを別途検証した。利益の出るプランが存在しても、その獲得余地が無制限とは限らない。

### 再発防止手順

1. 最小集計単位を「獲得月×プラン」に固定する。
2. 契約者解約率と売上解約率を別名で保存する。
3. 全体MRRはプラン別予測の合計から求める。
4. CACの集計対象と、評価する新規契約者の対象を一致させる。
5. プラン変更を単純な解約・新規獲得として二重計上しない。

プラン間移動が多い事業では、移動元・移動先を持つ履歴が必要になる。必須7カラムは計算の入口として有効だが、移動の追跡に必要な事実をすべて保持できるわけではない。

## 6.3 事例3：年払いの入金を利益と見なし、返金資金が不足した

### 発生した失敗と数値への影響

年額120,000円のプランで、入金日に「回収済み」と判定していた。月額換算ARPUは10,000円、月次の提供原価は2,000円、粗利率は80％、CACは48,000円である。

解約を置かない単純計算では、粗利によるCAC回収は6ヶ月となる。しかし資金繰り表には、初月の入金からCACと当月原価を引いた70,000円が余剰として表示され、別の獲得施策へ振り向けられた。

この契約では、3ヶ月利用後に解約すると未利用9ヶ月分を返金する取り決めになっていた。実際に解約が起こると、次の結果になった。

| 時点・項目 | 金額 |
|---|---:|
| 契約時の入金 | ＋120,000円 |
| 獲得費の支出 | −48,000円 |
| 3ヶ月分の提供原価 | −6,000円 |
| 未利用9ヶ月分の返金 | −90,000円 |
| 当該契約の最終収支 | −24,000円 |

3ヶ月の売上相当額は30,000円、粗利は24,000円であり、獲得費を回収できていない。最初に多く入金された事実は、この損失を変えない。

### 原因分析と完全復旧

原因は、契約金額、売上、入金、利用可能資金を一つの数字で扱ったことだった。必須カラムにあるARPUと粗利率だけでは、入金時期や返金条件は分からない。

復旧では、契約単位で入金済額、提供済期間、未提供期間、返金可能額を整理した。3ヶ月経過時点で90,000円の返金可能性がある契約については、その金額を資金需要として見えるようにした。全員が同時に解約する想定と、通常の解約実績を使う想定を分け、必要資金の幅を確認した。

不足分の調達や支出調整まで完了して初めて、資金繰り上の復旧となる。表の修正だけでは、既に使った現金は戻らない。実際の会計処理は契約条件と適用方針に従い、分析上の月額換算値とは分けて管理する。

### 再発防止手順

1. ARPUは月額換算値として統一する。
2. 入金日、入金額、返金日、返金額は別明細に残す。
3. 粗利による回収月と、現金収支による回収時点を別表示する。
4. 年払い比率の上昇時には、将来の提供原価と返金負担を更新する。
5. 月末残高だけでなく、日次の最低現金残高を確認する。

三つの事例に共通するのは、計算式の誤りよりも、入力値の意味と時間軸の不一致が先に起きている点である。復旧記録には、修正前後の数値、原因、影響した判断、再計算に使った入力、確認者を残す。翌月の担当者が同じ結論を再現できる状態が、復旧完了の条件となる。
