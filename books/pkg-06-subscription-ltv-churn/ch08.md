# 第7章 月次・日次運用の自動化スクリプト応用レシピと監査チェックリスト

本章では、必須7カラムのCSVを検証し、プラン別指標を計算して公開する処理を組み立てる。使用するのはPython標準ライブラリだけである。処理を「入力固定」「検証」「計算」「公開」に分けることで、途中失敗時に不完全な結果が利用されることを防ぐ。

前提は、月初契約者が当月の粗利を生み、月末に解約するモデルである。算出するLTVは割引前の期待粗利であり、固定費や運転資金を差し引いた企業利益ではない。返金、年払い、プラン移動を扱う場合は、別明細と追加モデルが必要になる。

## 7.1 レシピ1：入力の意味を壊さずに検証する

金額と割合には`Decimal`を使う。二進浮動小数点による丸め差を避け、入力された十進数をそのまま扱える。以下の関数は、後続のコードと同じファイルへ配置する。

```python
import csv
import hashlib
import io
import json
from decimal import Decimal, InvalidOperation

COLUMNS = (
    "plan_id", "plan_name", "active_users", "arpu_jpy",
    "gross_margin_pct", "monthly_churn_pct", "cac_jpy",
)
NUMBERS = COLUMNS[2:]

def number(value, column, line):
    try:
        result = Decimal(value.strip())
    except (InvalidOperation, AttributeError):
        raise ValueError(f"{line}行目: {column}は数値必須")
    if not result.is_finite():
        raise ValueError(f"{line}行目: {column}は有限値必須")
    if result < 0:
        raise ValueError(f"{line}行目: {column}は負数不可")
    return result

def read_plans(raw):
    text = raw.decode("utf-8-sig")
    reader = csv.DictReader(io.StringIO(text, newline=""))
    headers = reader.fieldnames
    if (headers is None
            or len(headers) != len(COLUMNS)
            or set(headers) != set(COLUMNS)):
        raise ValueError("ヘッダー不一致または重複")

    plans, seen = [], set()
    for row in reader:
        line = reader.line_num
        if None in row or any(v is None for v in row.values()):
            raise ValueError(f"{line}行目: 列数不一致")
        plan_id = row["plan_id"].strip()
        plan_name = row["plan_name"].strip()
        if not plan_id or not plan_name:
            raise ValueError(f"{line}行目: 識別子と名称は必須")
        if plan_id in seen:
            raise ValueError(f"{line}行目: plan_id重複")

        values = {
            key: number(row[key], key, line)
            for key in NUMBERS
        }
        users = values["active_users"]
        if users != users.to_integral_value():
            raise ValueError(f"{line}行目: 契約者数は整数必須")
        for key in ("gross_margin_pct", "monthly_churn_pct"):
            if values[key] > 100:
                raise ValueError(f"{line}行目: {key}は100以下")
        seen.add(plan_id)
        plans.append({
            "plan_id": plan_id,
            "plan_name": plan_name,
            **values,
        })
    if not plans:
        raise ValueError("データ行がありません")
    return plans
```

この検証では列順を問わず、余分な列は受け付けない。仕様追加を黙って無視しないためである。拡張列が必要なら、仕様版を更新して対応する。

`monthly_churn_pct=0.02`は0.02％として受理される。これが本来2％だったかどうかは、CSV単独では判定できない。月初母数と解約明細との照合を別工程に置く。全角数字や桁区切りのカンマなども、入力側で表記を統一し、受け側で推測して補正しない。

## 7.2 レシピ2：回収不能と未回収を分ける

回収月数を無期限に探索すると、回収できないプランで処理が終わらなくなる。先にLTVとの大小を確認し、その後、定めた期間内だけ月次累積を計算する。

```python
D = Decimal
ZERO, ONE, HUNDRED = D("0"), D("1"), D("100")

def metrics(plan, horizon=120):
    if horizon < 1:
        raise ValueError("探索期間は1ヶ月以上")
    users = plan["active_users"]
    arpu = plan["arpu_jpy"]
    margin = plan["gross_margin_pct"] / HUNDRED
    churn = plan["monthly_churn_pct"] / HUNDRED
    cac = plan["cac_jpy"]
    gross = arpu * margin
    keep = ONE - churn

    if gross == ZERO:
        ltv = ZERO
        ltv_state = "粗利ゼロ"
    elif churn == ZERO:
        ltv = None
        ltv_state = "一定条件では上限なし"
    else:
        ltv = gross / churn
        ltv_state = "算定済み"

    month = None
    if cac == ZERO:
        month, state = 0, "獲得費ゼロ"
    elif gross == ZERO:
        state = "回収不能"
    elif churn > ZERO and cac > ltv:
        state = "回収不能"
    elif ZERO < churn < ONE and cac == ltv:
        state = "有限月では回収しない"
    else:
        total, survival = ZERO, ONE
        state = "探索期間内に未回収"
        for current in range(1, horizon + 1):
            total += gross * survival
            if total >= cac:
                month, state = current, "回収"
                break
            survival *= keep

    return {
        "plan_id": plan["plan_id"],
        "mrr_initial_jpy": users * arpu,
        "mrr_after_12_churns_jpy": users * arpu * keep ** 12,
        "gross_ltv_jpy": ltv,
        "ltv_state": ltv_state,
        "cac_limit_12m_jpy": sum(
            (gross * keep ** t for t in range(12)), ZERO
        ),
        "payback_month": month,
        "payback_state": state,
        "search_horizon_months": horizon,
    }
```

`cac_limit_12m_jpy`は、12ヶ月分の期待粗利で回収できるCACの上限である。固定費、安全余裕、資金調達費用を考慮するなら、これより低く設定する。

解約率ゼロでは、永続する粗利を有限のLTVへ変換できない。大きな仮の数字で埋めず、値を空にして状態を併記する。逆に解約率100％なら、初月の粗利だけが発生する。

また、0％より大きく100％未満の解約率では、CACがLTVと等しい場合、累積粗利は有限月ではCACに届かない。この境界を「回収不能」と「探索期間内に未回収」の間へ埋没させない。

基本検算は、手計算できる条件で行う。

| 月次粗利 | 解約率 | CAC | 期待する判定 |
|---:|---:|---:|---|
| 8,000円 | 0％ | 48,000円 | 6ヶ月目 |
| 8,000円 | 2％ | 120,000円 | 18ヶ月目 |
| 2,100円 | 10％ | 60,000円 | 回収不能 |
| 8,000円 | 100％ | 8,000円 | 1ヶ月目 |
| 8,000円 | 2％ | 400,000円 | 有限月では回収しない |

丸めは表示時に限定する。途中で生存確率や累積粗利を整数へ丸めると、回収月の境界が変わることがある。

## 7.3 レシピ3：入力を固定し、結果を一括公開する

同じ処理の途中でCSVが更新されると、検証した内容と計算した内容が食い違う。入力は一度だけバイト列として読み、検証とハッシュ計算の両方で使う。

公開ファイルには結果と実行情報を一緒に格納する。別々のファイルへ書くと、片方だけ更新される可能性があるためだ。

```python
import os
import tempfile
from datetime import date, datetime, timezone
from pathlib import Path

MODEL_VERSION = "cohort-month-end-v1"

def atomic_publish(path, document):
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    name = None
    try:
        with tempfile.NamedTemporaryFile(
            mode="w", encoding="utf-8", newline="\n",
            dir=path.parent, prefix=".pending-",
            delete=False
        ) as stream:
            name = stream.name
            json.dump(
                document, stream, ensure_ascii=False,
                indent=2, default=str, allow_nan=False
            )
            stream.write("\n")
            stream.flush()
            os.fsync(stream.fileno())
        os.replace(name, path)
        name = None
    finally:
        if name is not None:
            Path(name).unlink(missing_ok=True)

def execute(source, output, as_of, horizon=120):
    date.fromisoformat(as_of)
    raw = Path(source).read_bytes()
    digest = hashlib.sha256(raw).hexdigest()
    key = {
        "as_of": as_of,
        "source_sha256": digest,
        "model_version": MODEL_VERSION,
        "horizon_months": horizon,
    }
    output = Path(output)
    if output.exists():
        old = json.loads(output.read_text(encoding="utf-8"))
        if old.get("run_key") == key:
            return "既存結果を維持"
        raise ValueError("既存成果物と実行条件が異なります")

    plans = read_plans(raw)
    result = {
        "run_key": key,
        "created_at": datetime.now(timezone.utc).isoformat(),
        "plan_count": len(plans),
        "rows": [metrics(plan, horizon) for plan in plans],
    }
    atomic_publish(output, result)
    return "公開完了"
```

金額はJSON内で文字列になる。後段では`Decimal`へ戻してから演算し、文字列の大小比較をしない。

この公開方法は、同じファイルシステム上での置換を前提とする。読者が書きかけのファイルを読むことを避けられるが、同時実行の排他制御や、停電時の完全な永続性まで保証するものではない。スケジューラ側で同一成果物への並行実行を禁止し、保存先の性質を確認する。

同じ実行キーなら再計算せず、異なる条件なら上書きを拒否する。訂正時は版を付けた別の出力先を指定し、旧版との対応を残す。ハッシュは入力の同一性を確認する手段であり、入力内容の正しさを証明するものではない。

## 7.4 日次・月次バッチへの組み込み

起動部分を次のように加える。コマンド文字列を組み立てて別プロセスへ渡す必要はない。

```python
if __name__ == "__main__":
    import argparse
    import sys

    parser = argparse.ArgumentParser()
    parser.add_argument("--source", required=True)
    parser.add_argument("--output", required=True)
    parser.add_argument("--as-of", required=True)
    parser.add_argument("--horizon", type=int, default=120)
    args = parser.parse_args()
    try:
        message = execute(
            args.source, args.output, args.as_of, args.horizon
        )
    except (OSError, ValueError, ArithmeticError) as error:
        print(f"処理中止: {error}", file=sys.stderr)
        sys.exit(1)
    print(message)
```

日次処理では、前日までの確定明細からスナップショットを作り、契約者数、未収、返金、現金残高の変化を追う。月次解約率を日々の観測値から無理に更新せず、未確定月は暫定値として表示する。日次解約率を使う場合も、単純に30倍して月次率にはしない。

月次処理は、締め完了、入力検証、計算、差分確認、公開、後続更新の順に連携する。前段の成功終了と対象月の一致を条件にし、「毎月1日の一定時刻になったから実行する」だけでは連携しない。

終了コードが非ゼロなら後続処理を止め、直前の正常版を残す。ただし画面には対象月と最終成功日時を表示し、古い値を最新値として見せない。通信障害は再試行の対象にできるが、重複識別子や割合の不整合は入力修正が必要である。

遅延到着した解約や返金は、締め後訂正版として再計算する。新旧の差額、訂正理由、承認記録を残し、比較資料でもどの版を使ったか追跡できるようにする。

## 7.5 実務監査チェックリスト

### 入力と集計の確認

- [ ] 必須7カラムがそろい、plan_idが一意である。
- [ ] 契約者、アカウント、席数のどれを数えるか明文化されている。
- [ ] ARPUの対象期間と税込・税抜の扱いが統一されている。
- [ ] 年払い金額が月額換算されている。
- [ ] 割合は百分率で保存され、解約明細との照合が済んでいる。
- [ ] CACの費用範囲、獲得期間、対象人数が一致している。

### 計算と判断の確認

- [ ] 月初・月末の解約タイミングが明記されている。
- [ ] 12ヶ月後の残存MRRと、12ヶ月累積粗利が区別されている。
- [ ] 解約率ゼロ、100％、粗利ゼロの結果を確認している。
- [ ] 回収不能と探索期間内の未回収が区別されている。
- [ ] プラン別予測を合計して全体予測を作っている。
- [ ] 少数契約や観測期間の短いコホートを識別できる。

### 公開と復旧の確認

- [ ] 入力の保管先、ハッシュ、対象日、モデル版を記録している。
- [ ] 同じ成果物を複数の処理が同時に更新しない。
- [ ] 検証失敗時に公開結果を更新しない。
- [ ] 正常版へ戻す手順と担当者が決まっている。
- [ ] 訂正版と旧版の関係を追跡できる。
- [ ] 粗利回収とは別に、返金を含む現金収支を確認している。

チェック欄には、確認日、確認者、証跡の所在も添える。「問題なし」という記録だけでは翌月の再検証に使えない。入力、式、公開結果、判断の根拠を一続きで追えるようにしておくことで、定例運用と障害時の復旧を同じ手順で支えられる。
